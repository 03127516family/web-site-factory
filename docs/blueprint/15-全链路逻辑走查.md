# 15 · 全链路逻辑走查（2026-07-03，AI 逐链亲走的实证记录）

> **背景**：用户指令"先理论，已有的也不一定对，可改可删，主要必须你走一遍"。本文是走查记录：8 条链逐步走，每一步对数据问三个问题——**从哪来？谁有权改？改了之后谁知道？**——三问答不圆的地方就是不自洽。全部发现基于对代码/模版/内容的逐行核实（引用处标了文件与行为证据），不是照旧文档转述。
> **结论先行**：主干成立（MD 真相源 + 确定性渲染 + 三级编辑，逻辑闭环）；但查出 **2 处真相源级分裂（F1/F2，必须修）+ 5 处结构性薄弱（F3–F7）**。修复方向全部是"删东西、并源头"——系统修完比现在更简单，不是更复杂。

## 1. F1 · 真相源分裂：页面元数据有两个家（**最重的发现**）

**证据**（`scripts/build.mjs:18-98` vs `src/content/*.md` frontmatter）：

| 数据 | 家 1：`pages[]`（代码里的手写数组） | 家 2：MD frontmatter | 矛盾 |
|---|---|---|---|
| slug | `"products/single-girder-eot-cranes"` | `slug: single-girder-eot-cranes` | 双处登记，格式还不同（带不带前缀） |
| template | `"src/templates/product.html"`（文件路径） | `template: product@1`（族@版本） | 双处、两套命名体系 |
| **title / description / lang** | **只在 pages[]（代码）里** | 无 | **内容值住在代码里** |

三问全崩：title 从哪来？——代码文件。谁有权改？——只有会改代码的人；**运营在编辑器里改不了页面标题**，可 title 明明是三级编辑模型里最典型的 L1 值。改了谁知道？——SEO（og:title）、`<title>`、sitemap 全吃它，但它绕过了整个"MD 真相源"体系。

**这不是新问题，是过渡态没兑现**——`build.mjs:17` 原注释自己写着："将来一个 MD 一个产品页时，这里按 content 目录展开即可"。走查结论：**兑现它的时机就是现在（批量搬迁前）**，因为搬迁每加一页就往错误的家里再塞一条。

**修复形态（删代码，不是加代码）**：
- MD frontmatter = 页面完整元数据（title/description/slug/type/lang/template）——**登记即内容，内容即登记**；
- build 扫 `src/content/` 目录派生登记表，`pages[]` 手写数组**删除**；
- 连锁收益：运营能点改 title/描述（L1 归位）；"网站管理"的实体=内容目录（`ls` 即页面列表，产品期后台列表=读目录）；多语言 `content/en/` 自然并入登记（12 章机制零改动）；SEO 取值单源。

## 2. F2 · 验证双源 + 覆盖缺口 2/7

**证据**（`scripts/verify-geom.mjs:23-35`）：verify-geom 自带一份 `PAGES` 注册表（**只有 single-girder 和 overhead 两项**）+ 自维护一份 `compose()`。三问：geom 验哪些页由谁定？——第二份手写表。build 的登记变了 geom 知道吗？——**不知道**（compose 双份已经踩过坑，坑账#4；注册表双份是同一病灶）。

**当下真实状况：7 页里只有 2 页在几何回归保护之下。** 3 篇 post 和 2 个产品页改坏了版式，check 照样全绿——"改完必验"的承诺对 5/7 的页面是空的。

**修复形态**：verify-geom `import { pages } from build.mjs`（单源）；baseline 作为每页登记的可选字段；**每页必须有基准**——还原页基准=原站快照；AI 设计的页（posts）基准=人审通过那一刻的自身渲染快照**冻结入库**（"祝圣"机制，见 F5）；覆盖 7/7。

## 3. F3 · 引擎的四张名字注册表——读写不对称表就是债务地图

**证据**（`scripts/render.mjs:22-50`）：引擎里有四张按名字键的表：`REPEATS`（读：repeat 名→数据取法）、`REPEAT_FM_ARRAY`（写：repeat 名→frontmatter 写回路径）、`REPEAT_BODY_BLOCKS`、`NO_STRUCT_EDIT`。把读写两张表并排看，**不对称的行恰好全是已知债务**：

| repeat 名 | 读（渲染取自） | 写（编辑写回） | 判定 |
|---|---|---|---|
| gallery / specs / cases | 同一路径 | 同一路径 | ✅ 干净 |
| components | `components.items` | `components_images` | ⚠ 双处结构（台账#1） |
| crane-types | `crane_types.items` | `crane_types_images` | ⚠ 同上 |
| related-products | `related_products.items` | `related_products.seed` | ⚠ 存在"seed→items"派生层，真相是 seed |

走查结论：**"渲染侧与编辑侧对称"铁律在这三行是破的**——读的和写的不是同一份数据，中间有一层隐式派生。修复方向不变（台账#1/#4：单一 frontmatter 结构 + 注册表塌缩进模版 `data-array`），但走查给了它精确的完成判据：**修到读写两表逐行相同，然后两表一起删掉**。排期维持 P2（搬迁后），因为它不阻塞加页；但凡动这三个区的结构，先还这笔债再动。

## 4. F4 · 面包屑结构存在 5 份拷贝

**证据**：`product-superset.html:48-50`、`product.html`、3 份 post 骨架（如 `posts/gantry-cranes-for-sale.html` 开头）——同一个 toptitle/breadcrumb 块（含过时 RDFa `xmlns:v`）逐字出现 5 次。三问：面包屑结构改一次要动几处？——5 处。这和当初询盘表单"5 份模版逐字复制"是**同一个病**（2026-07-01 已治过表单：抽 fragment）。

**修复形态（比原 1.2 方案更对）**：面包屑抽成 `src/fragments/breadcrumb.html`（结构 1 份，含新的 JSON-LD 出口），数据取每页 MD 的 `breadcrumb.trail/current`——原计划"逐模版改造面包屑"作废，改为"抽 fragment 一次治五处"。顺手删 RDFa 与 related 区旧词汇（台账#8）。

## 5. F5 · geom 基准的生命周期没有定义（版式变更的逻辑缺口）

走查链 D 时发现：geom 的全部逻辑建立在"与基准 1:1"上，但**改版式就是故意不 1:1**。现有文档只说"预期变化逐条解释"（06 §3），没回答关键三问：新版式谁批准？批准后基准从哪来？旧基准去哪？

**补全（基准祝圣流程）**：改版式 → 全族重渲 → 人审通过 → **将新产出快照显式提交为新基准**（commit message 注明"基准更新：<原因>"）→ 此后 geom 对新基准。posts 这类无原站基准的页，创建时人审通过的首次渲染就是初代基准。基准更新必须是**独立、显式、带理由的提交**——防"顺手把验证标准改成自己的输出"这种自我欺骗。

## 6. F6 · 反向传播缺口（新页 → 旧页）

12 章传播矩阵回答"改一处，谁跟着动"，但**加一页**时要动的是"别的页"：某些旧页的 `related_products.seed` 该添它、header 导航该挂它。矩阵没有这一行，只有 SOP-1 第 8 步的人工核对兜着。**处置**：矩阵补第十行"新增页面"（下游=导航 fragment + 相关页 seed，现阶段人工核对，M2 起由关系数据派生）；承认这是现阶段全系统仅剩的两个"靠人记得"点之一（另一个是给料）。

## 7. F7 · post 骨架的复制权衡（确认 + 说清，不改）

**证据**：骨架是纯 body（无 head/header/footer 重复，chrome 由 compose 组装）✅；但族内共同结构（toptitle、TOC 容器、`.craneinfo` 骨架规则）随篇复制。这是"版式自由优先"的**已知代价**，走查确认可接受；缓解路径=共同块逐个 fragment 化（面包屑 F4 先行），若未来 post 出现"标准版式聚类"，抽一份 post-standard 模版把聚类页收编成族。

## 8. 走查确认为"自洽"的部分（同样是结论）

- 烧 MD→渲染→编辑→写回的**坐标闭环**（fm:/mdhead:/mdbody: 读哪写哪）——走通，无缺口；
- mode/type 路由（判断权归调用方）——走通；
- fragments 注入（inquiry-form）——走通（前提：F2 修掉 compose 双份）；
- 多语言 12 章机制——走通，且 F1 修复后 locale 维度零成本并入；
- 状态=git 投影、发布=原子重发——逻辑闭环；
- 三级编辑模型的物理推导（02 原理 4）——走查未发现反例。

## 10. 走查后的系统一句话（修复完成时成立）

> **一个页面 = 一份 MD 文件**：它的元数据是登记、frontmatter 是值、正文块是内容、模版按 marker 装配它、geom 拿它的基准验它、编辑器按坐标写回它、sitemap/SEO/管理列表全是"扫一遍内容目录"的派生物。**系统里不存在第二个需要人工同步的登记处。**

——走查通过的标准就是这句话每个分句都为真。现状离它差 F1/F2/F4 三步，全是删东西。
