# 12 · 修改传播与多语言同步（内容生命周期）

> 本章回答运营期的四个问题：**改一处，哪些东西要跟着动？日常编辑怎么闭环？中文改了，英文怎么知道、怎么只翻改动的部分、怎么不覆盖人工润色？长期维护要干什么？**

## 1. 改动传播矩阵：一处改动，哪些跟着动

系统里一共只有十种改动。每种改动的下游反应必须是**确定的、可枚举的**——这张表就是运营期的"因果地图"：

| 改了什么 | 自动跟着动（build/任务内，零人工） | 需要任务或人的 | 多语言侧反应 |
|---|---|---|---|
| **值**（L1：某页文字/图/链接） | 该页重渲；sitemap `lastmod` 更新 | 发布（人点按钮） | 目标语言该**字段**标记过期（§3.3） |
| **结构**（L2：某页加/删/调序段落） | 该页重渲 + validateBlocks | 发布 | 目标语言出现**结构差**：新段=未翻译字段（`data-optional` 优雅缺省，页面不塌）；删段=同步时删除 |
| **版式**（L3：超集模版 / post 骨架） | **全族重渲 + geom 回归** | agent 执行 + 发布 | **零成本**——模版全语言共享、marker 不含语言，换版式所有语言页自动跟上（本架构最大的多语言红利） |
| **chrome fragment**（header/footer/询盘表单） | 全站重渲 | 发布 | 每语言各有一套 fragment（§3.1），改哪套动哪个语言的全站 |
| **站点级值**（`site.md`：电话/邮箱/地址/社媒/备案号，04 章 §8） | 全站重渲（fragments 按 `site.*` 取值） | 编辑器点改 + 发布 | 每语言一份 `site.md`（号码通常共享、文案各语言） |
| **引擎**（scripts/） | 全站重建 | **全站 geom 回归**（升级纪律，§4.2）+ 发布 | 全语言一起回归 |
| **素材**（图片替换/新增） | 引用页重渲；CDN 缓存刷新 | 过图片闸门（SOP-6） | 图默认跨语言共享；alt 文本是字段→随字段翻；语言特供图=目标 MD 直接换文件名 |
| **SEO 数据**（`seo.*` frontmatter） | 该页 head 重生成 | 发布 | 每语言独立维护自己的 `seo.*` |
| **slug** | —— | **专门流程**（危险操作）：301 映射表登记 → 全站内链检查 → 各语言 hreflang/sitemap 更新 → 发布 | 各语言 slug 可独立，但逻辑配对键不变（§3.7） |
| **新增页面**（烧新 MD 入库，走查 F6 补） | 该页构建 + sitemap 自动收录（登记由目录派生后天然成立） | **反向核对**（新页→旧页）：header 导航该不该挂它、哪些旧页的 `related_products.seed` 该添它——SOP-1 第 8 步，现阶段人工核对，M2 起由关系数据派生 | 各目标语言出现一个"未翻译页"（§3.2 状态机起点） |

两条纪律：
1. **表外无改动**——出现表外的新改动种类，先补这张表再动手。（本条已执行两次：2026-07-03"站点级值"第九种、同日走查 F6"新增页面"第十种——均先补表、后落设计。）
2. **slug 变更永远走专门流程**，不许当普通编辑做（它是唯一会打断外部链接与搜索索引的改动）。

## 2. 日常编辑/修改闭环（回指，不重复）

- 谁能改什么：[01 章](01-目标边界与停止准则.md) 三级编辑模型（值→编辑器；结构→MD；版式→agent+geom）。
- 怎么操作：[05 章](05-工作流程SOP.md) SOP-4/5/8；产品形态映射见 [10 章 §4](10-产品化形态与路线.md)。
- 最小闭环（产品期）：**改（编辑器点改）→ 保存=commit（作者=登录用户）→ 构建任务自动跑（含 validate/geom）→ 待发布 → 发布者点发布**。中间任何一步红了，改动停在草稿态，线上无感。
- 审计免费：每次保存都是一个带作者的 commit，"谁在什么时候改了哪个字段"永远可查。

## 3. 多语言同步：正式设计

### 3.0 设计总则：站点无关性与复用判据（2026-07-04 系统化补强）

> 本节回答"以后别的站、别的模版怎么复用这套多语言逻辑与代码"——判据必须可机器验证，不靠自觉。

**分层归位**（[17 章四层切分](17-引擎与站点分离.md)在多语言维度的映射）：

| 层 | 多语言相关内容 | 换站点/换模版时 |
|---|---|---|
| **引擎**（scripts/ + editor.js） | 版本戳的加/比/写（按坐标操作，不认字段名）、状态推导纯函数、翻译任务框架 | **零改动**（判据同 17 章：第二个站的 PR 里引擎目录 diff=空） |
| **契约**（markers + 坐标系） | **可翻译坐标系 = 可编辑坐标系**——同一套 `fm:/mdhead:/mdbody:` 坐标，编辑器写回用它，版本戳也按它记；范围仅差一份锁翻译清单（U-1） | 零改动 |
| **站点**（site.config + fragments + glossary） | `langs / sourceLang / deployLangs / xDefault / ogLocale 映射`；每语言 chrome fragments；U-1 锁翻译清单、U-2 术语表 | 每站自己声明 |
| **内容**（MD） | `i18n_rev / translated_rev / manual` 戳，随 MD 进 git | 每站自己的内容 |

三条硬判据（可验证的那种，不是口号）：
1. **引擎 grep 不到**任何语言代号/字段名/站点域名——§2 家规（引擎不认名字）在 i18n 维度的延伸；"源语言是中文"不许硬编码，由 `site.config` 的 `sourceLang` 声明（换一个用英文创作的站=改配置）。
2. **一切状态可重算**：缺失/过期/冲突 = 纯函数 `f(内容目录, site.config) → manifest（§3.1.1）`，删掉缓存重扫结果不变。今天这个函数喂 CLI `check`，将来**同一个函数**喂后台 API——两个前端、一个内核（同 render 字符串入口的思路，⑲）。
3. **editor.js 零改动**：+戳发生在保存链路的**服务端**（edit-server 收到坐标+新值 → 写值 + 加戳，同一次提交）；编辑器只按坐标写值，连"多语言"三个字都不知道。

### 3.1 数据模型

```
src/content/<slug>.md            ← 源语言（中文，权威）
src/content/en/<slug>.md         ← 目标语言镜像（路径镜像 = 逻辑配对键）
src/templates/…                  ← 全语言共享（marker 无语言）
src/fragments/zh/… , /en/…       ← chrome 每语言一套（导航/页脚文案，启用多语言时把现有 fragments 迁入 zh/）
build.mjs::pages[] × locale      ← 输出 /zh/… 与 /en/…
```

- 目标语言 MD **也是真相**：结构与源镜像，值是译文；它同样可以被编辑器点改（英文运营润色走同一套 L1 流程）。
- 同步状态靠**字段版本戳**（2026-07-03 ⑳ 拍板：编辑事件驱动为主线，git 降为兜底）：

```yaml
# 源 MD（中文，权威）：每个可翻译字段一个版本戳。编辑器改哪个字段，保存时 +1 哪个
# （坐标本就是它写回 MD 的定位键，天然知道你改的是 overview）。
i18n_rev:
  hero.title: 2
  overview: 5

# 目标 MD（英文）：记录每字段「译自源的哪个版本戳」+ 兜底锚点
i18n:
  source: zh
  translated_rev:
    hero.title: 2          # == 源戳 → 该字段已同步
    overview: 4            # < 源戳 5 → overview 段过期，待重译
  source_commit: 3f9a2c1   # 兜底用：仅当有人绕过编辑器直接改源时，才用它做 git diff 补清单
```

#### 3.1.1 多语言关联清单（manifest）——把一篇的各语言版本显式串起来的那张表

> 起因（2026-07-04）：用户指出"没看见任何关联关系，像是我让你翻你才翻"。底层机制（镜像路径配对 + 版本戳）**是隐式**的，散在各 MD 里。管理软件与运营需要一张**显式聚合表**：一篇逻辑页 → 它有哪些语言、各自 MD/HTML 在哪、什么状态、哪几段过期。这张表就是"关联关系"，也是让同步从"人开口才翻"变成"系统持续盯着、主动提醒"的关键。

**逐逻辑页一条记录**（配对键 = 镜像相对路径，跨语言不变）：

```json
{
  "key": "posts/crane-lifting-safety-training",     // 逻辑页身份（跨语言唯一）
  "type": "post",
  "targetLangs": ["zh-CN", "en-US", "fr-FR"],        // 该页【应有】哪些语言 —— 来自 site.config
  "versions": {
    "zh-CN": { "md": "content/zh/posts/crane-lifting-safety-training.md",
               "html": "/zh/posts/crane-lifting-safety-training/",
               "status": "published", "rev": { "title": 3, "overview": 5 } },
    "en-US": { "md": "content/en/posts/crane-lifting-safety-training.md",
               "html": "/en/posts/crane-lifting-safety-training/",
               "status": "stale", "staleFields": ["overview"],
               "translatedRev": { "title": 3, "overview": 4 } },
    "fr-FR": { "md": null, "html": null, "status": "missing" }   // 该有、尚未生成
  }
}
```

**它是派生索引，不是第二真相**（呼应 F1 与 [00 章 ⑧](00-系统总流程.md)"DynamoDB 存非真相元数据、页面列表从内容目录派生"）：
- `targetLangs`（应有哪些语言）= **声明**，取自 `site.config`；
- `versions.*`（实际有哪些、路径、状态、过期字段）= **扫内容目录 + 读各 MD 版本戳**算出来；
- 可随时删掉重扫重建。产品期缓存在管理库（DynamoDB），每次 保存/翻译/发布 事件后更新。

**它改变了什么**：没有这张表，系统不持续知道英文缺没缺、旧没旧 → 只能"人点翻译才翻"。有了它，改中文某段 → 源该字段 +戳 → **该记录里对应语言的 `staleFields` 自动多一项、`status` 变 stale** → 后台那篇旁自动亮"EN：待更新"。同步由被动变主动（甚至可设自动触发）。

### 3.2 每页每语言的同步状态机

```
未翻译（目标 MD 不存在）
  → 翻译中（翻译任务运行，写 draft 分支）
  → 待审（译文草稿 + 预览就绪，等双语审核）
  → 已同步（逐字段：目标 translated_rev == 源 i18n_rev）
  → 已过期（某字段 目标 translated_rev < 源 i18n_rev → 该字段进「待更新」清单）
  → 冲突待人工（源该字段过期，且目标侧同一字段被人工改过 → 机器不碰，人裁决）
```

后台页面列表因此能显示："EN：3 处过期，1 处冲突" ——运营看得见、点得动。**过期是两个当前 MD 里的版本戳数字一比即知，不取历史。**

### 3.3 过期检测：编辑事件驱动（主线）+ 版本戳比对；git 仅兜底（2026-07-03 ⑳ 用户拍板）

**主线（编辑事件驱动，不依赖 git）**：编辑器每次写回都带**字段坐标**（`overview` / `hero.title`…——本就是它定位 MD 写回点的键）。保存值的同时，给源 MD 里该字段的**版本戳 +1**（`i18n_rev.overview: 4→5`）。目标语言 MD 记着自己译自的版本戳（`translated_rev.overview: 4`）。**过期 = 目标戳 < 源戳**——两个当前 MD 里的数字一比即知，不取任何历史版本、不碰 git。改一个字段只 +1 那一个戳，所以"待更新清单"天然精确到字段（改 `overview` 一段，只有 `overview` 过期，标题/其他段/英文人工润色一律仍算已同步）。

- 信号来源是**编辑动作本身**，不是事后算：你按下保存的瞬间，"这篇、这个字段、变了"就是确定的（这正是"可见即可编辑"编辑器天然产出的副产品）。
- 版本戳是 MD frontmatter 里的普通字段，人类可读、随 MD 进真相、跨语言各存各的、零数据库。

**加戳的位置与编辑器提示（2026-07-04 补，引擎纯度）**：+1 发生在保存链路的**服务端**（edit-server：patchMarkdown 写值 + `i18n_rev` 加戳，同一原子提交）；editor.js 零改动。保存响应可顺带返回受影响语言（读 manifest 一眼便知），编辑器界面提示"此修改将使 EN:overview 过期"——提示是免费副产品，**不是**编辑器长出了同步逻辑。

**兜底（源被绕过编辑器改动时才用）**：若有人**直接手改 MD 文件 / 让 AI 整篇重烧**（没有编辑事件、没 +戳），则该篇退化为"整篇待复核"；此时**可选地**用 `git show <source_commit>:<path>` 取上次同步版、与当前源做一次结构化字段比对，补出精确清单。**这是降级路径，非主线**——日常内容修改走编辑器就用不到 git。旧 spec §13 手搓 `(block-id, field)+hash` 表想要的能力，主线用"编辑时 +戳"免费拿到，git 差异引擎退居兜底。

**人工润色保护（本模型下天然成立）**：英文侧手改 `overview` 是目标侧编辑，不动源的 `i18n_rev`；只要中文 `overview` 没再被编辑（源戳没涨），目标戳仍 == 源戳，判"已同步"，翻译任务永不碰它。中文 `overview` 真的又改了（源戳涨）、而英文侧此前手改过该字段 → 标"冲突待人工"（§3.5）。

### 3.4 翻译任务（生成 worker 的变体，[11 章 §2.4](11-产品化架构.md) 同一套机制）

1. 输入：slug + 目标语言 + 待更新字段清单（来自 §3.3 主线的**版本戳比对**：目标戳 < 源戳的那些字段）。
2. agent **只重写清单内的字段/块**（提示词携带全页语境保证译文连贯，但写入范围严格限定）；写完把目标 MD 该字段的 `translated_rev` 抬到源当前戳（该字段即回到"已同步"）。
3. 跑内核自检（validateBlocks + build——结构不可能翻坏，坏了任务就红）→ 预览。
4. **人审**（双语审核语言质量——机器保证结构对，人保证话说得对）→ 每语言**独立发布**。
- 红线原样：翻译任务永不直接上线；失败可重试，不碰已发布内容。

### 3.5 人工润色保护与冲突（"机翻不许覆盖人改"）

- **天然保护**：任务只写"目标戳 < 源戳"的字段，其余字段永远不碰——所以英文侧的人工润色，只要对应的中文源没再被编辑（源戳没涨），该字段永远判"已同步"，**无论同步多少次都不会被覆盖**（机制保证，不靠自觉）。
- **冲突态**：中文该字段过期（源戳涨），而目标侧同一字段此前被人工改过 → 该字段**不自动重译**，标"冲突待人工"，任务报告里并排给出：源现文 + 目标的人工现文，人选择保留/重译/手改。检测"目标被人工改过"用目标 MD 侧的字段标记（如英文运营点改时打 `manual` 标）——同样不依赖 git 历史。
- 这继承并落实旧 spec §13 的要求："被人工复核过的字段，源字段未变时不被机翻覆盖；源字段一变标记过期再重译"。

### 3.6 结构与版式变化的跨语言语义（矩阵第 2/3 行的展开）

- **源加一段** → 目标语言多一个"未翻译字段"：页面照常构建（`data-optional` 裁掉缺段，不塌）；过期清单里列为"新增待翻"。
- **源删一段** → 同步任务在目标侧同步删除（报告列明）。
- **改版式/换模版** → 全语言自动跟随，**零翻译成本**（模版共享、值不动）。这条与 HTML-真相源方案对比最悬殊——那边等于每语言每页重排一遍。
- **字段改名（key rename）** → 视为结构手术：由 agent 在**所有语言镜像上同一提交内完成**，不进翻译流程（改名≠改内容）。日常应避免——key 的稳定性就是配对的稳定性。
- **目标侧结构编辑禁止**（2026-07-04 补）：增删重复项/段落**只许在源语言页做**；目标语言页编辑器只开放值编辑（润色），结构增删 UI 不渲染（edit-server 按"本页是否目标语言"关闭，机制同 `data-no-add`）。否则镜像结构分叉，§3.3 的字段级配对全部失锚。若某市场真需要"目标语言独有内容"，那是"按市场定制"的**新命题**，届时另拍——不为它预开口子。

### 3.7 SEO 跨语言（[08 章](08-SEO与性能.md)的多语言延伸）

- **hreflang 成对生成**：逻辑配对键 = 镜像路径；`pages[] × locale` 同源产出每页的 `<link rel="alternate" hreflang>` 对——同源则不漏页、不错配。组内加 **`x-default`** 指向默认语言（zh）页，未匹配语言的访客/爬虫有明确落点。
- 每语言独立：canonical（各指自己）、sitemap（`/zh/sitemap.xml`、`/en/sitemap.xml`，各自提交站长平台）、`seo.*` 文案。
- 显示 slug 可按语言定制（目标 MD 的 `slug` 字段），逻辑配对不受影响；slug 变更走专门流程时**连带更新整组 hreflang**（§1 矩阵最后一行）。
- **头部语言切换器与 hreflang 同源**（2026-07-03 审计补）：header 里的语言切换链接用与 hreflang 同一份配对数据生成——每页指向自己的**镜像页**而不是对方语言首页；镜像页尚未翻译时，该语言项降级指向对方语言首页（可标"暂未翻译"）。可见 UI 与 SEO 声明永远一致，不会一个说有、一个说无。
- 语言元数据补齐：`og:locale`（zh_CN / en_US）+ `og:locale:alternate`；JSON-LD 补 `inLanguage`。
- **每语言独立上线闸 `deployLangs`**（2026-07-04 补）：site.config 声明"已对外语言"（现 `["zh"]`）；未列入的语言**可建、可预览、不部署、不进 sitemap/hreflang**——"机制就绪"与"对外上线"由一个配置位解耦。特别地：**en 对外必须等整站切换日**——老站英文页现活在域名根路径（`dgcrane.com/products/...`），`/en/` 提前上线 = 同域两套英文互撞（重复内容 + hreflang 与已收录页打架），与 robots.txt 接管同一时点（[08 §2.3](08-SEO与性能.md) 同款判断）。

### 3.8 实施时机与里程碑归属

- **现在（M0–M2）唯一要守的**：`/zh/` 前缀（已拍板）、marker 与模版不含语言、fragments 结构可拆语言目录、`i18n.*` 字段名预留。守住这四条，多语言随时可启用、零返工。
- **启用时（英文站拍板后，M3 或按需提前）**的落地顺序：fragments 拆语言目录 → `i18n:diff` 内核命令 → 首批页面全量翻译（也是走翻译任务，只是清单=全部字段）→ 状态徽标与同步按钮进后台 → hreflang/sitemap 接入。

### 3.10 审计与追溯："有迹可循"的完整清单（2026-07-04 系统化补强；同日经用户纠偏改为**能力接口制，不钉死 git**）

> 纠偏记录：本节初稿把每条痕迹都写成"git commit"，用户当即指出"后续哪有那么多 git？必须用 git 吗？"——这与 ⑳ 的教训同型（同步主线不许依赖 git，信号在编辑瞬间已产生）。改正如下。

**审计只依赖两个能力接口，不依赖任何具体实现**（这是继 存储缝 FS↔S3、函数缝 本地server↔Lambda、配置缝 之后的**第四条缝：历史缝**）：

| 能力接口 | 定义 | 本地阶段的提供者 | 产品期（后台）的提供者 |
|---|---|---|---|
| **事件记录** | 追加一条"谁/何时/哪个坐标/改成什么"（信号在保存请求里**天然齐全**，同 ⑳ 洞察——不是事后算出来的） | git commit（免费承载） | 保存链路顺手写 append-only 事件日志（DynamoDB/日志文件均可，**不必是 git**） |
| **版本化存储** | 取任意历史版本、支持回滚 | git | S3 版本化 或 git 远端（随[待拍板 #3](DECISIONS.md) 定） |

**关键分界——日常多语言同步一次都不碰这两个接口**：过期检测/翻译范围/润色保护/冲突判定（§3.3–§3.5 主线）只读**当前 MD 里的戳**；事件记录与版本化存储只服务"事后追责"与"回滚"两个场景。

| 事件 | 痕迹（与实现无关的部分） | + 事件记录（接口） | 能回答什么 |
|---|---|---|---|
| 源语言编辑 | `i18n_rev.<字段>` +1（在源 MD 里） | 一条编辑事件（作者/时间/坐标） | 谁、何时、改了哪个字段 |
| 翻译执行 | `translated_rev` 抬升 + 任务报告 | 一条翻译事件（范围=清单内字段） | 依据源的哪个版本、动了哪些字段、没动哪些 |
| 人工润色 | 字段 `manual` 标记（在目标 MD 里） | 一条编辑事件 | 哪些字段是人改的（=机翻永不覆盖的依据，§3.5） |
| 冲突裁决 | 裁决结果落目标 MD（保留/重译/手改） | 一条裁决事件 | 冲突怎么解的、谁拍的 |
| 状态快照 | manifest（§3.1.1，可随时重算） | ——（派生层，无需记录） | 任一时刻"每页每语言什么状态、哪几段过期" |

**追溯判据**（本节的验收标准）：任意一个目标语言字段的当前值——①"**译自源的哪个版本**"沿 `translated_rev → i18n_rev` 即答，**只读两个当前 MD**；②"**之后被谁动过**"问事件记录接口（本地=`git log`，产品期=事件日志查询）。判据本身不含"git"三个字母——换掉提供者，判据原样成立。
