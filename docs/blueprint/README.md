## 0. 一句话说清这个系统

> **一条确定性的静态站流水线：AI（agent）承担一切需要判断的创作，代码承担一切确定性的装配与验证，人只负责给料、拍板、验收。真相源是 git 里的 Markdown，任何页面永远可以从真相源一键重算出来。**

这句话描述的是**内核**（01–09 章）。**但内核不是终点：我们要做的是一个脱离本机的产品**——运营在浏览器里"贴内容 → AI 云端生成 → 可视化点改 → 一键发布"，全程不碰命令行、不依赖任何特定电脑。产品形态与路线见 **Part 2（[10](10-产品化形态与路线.md)/[11](11-产品化架构.md) 章）**；当前仓库定位 = 内核参考实现 + 首站（dgcrane）资产。内核的三种角色各占一层：

| 角色 | 负责什么 | 频率 |
|---|---|---|
| **确定性代码**（render / build / verify / 未来 deploy） | MD→HTML 装配、校验、发布。系统的本体 | 每次 build，免费、可复现 |
| **AI agent**（Claude Code 会话，未来可换任何 agent） | 创作类判断：裸文章→结构化 MD、真实页→模版、验证循环、搬迁执行 | 低频（加页面、加页族时） |
| **人**（现在=你；未来=运营） | 给料（文章/图/产品名/slug）、拍板（托管/表单/上线）、验收、日常在编辑器里改值 | 给料低频，改值高频 |

两条硬需求的落点（详见 [01 章](01-目标边界与停止准则.md)）：

- **「借助 AI 实现 ~80% 静态化」**——两重含义都成立并写死：①交付物 **100% 静态页面**，全站动态触点收敛到白名单 ≤3 个且全部外置（询盘提交、可选的搜索与客服脚本）；②生产工时 **AI ≈ 80%，人 ≈ 20%**（给料+拍板+验收），代码 0（免费）。
- **「可见即可编辑」**——三级编辑模型（**值 / 结构 / 版式**）：值一级全覆盖就地点改（`npm run edit`），结构一级改 MD 文本，版式一级走模版+验证。这个分层不是产品取舍，是可编辑性与自由度互斥的物理边界（原理见 [02 章](02-第一性原理.md)原理 4）。

```
        src/templates/*.html（页族模版，          │        └──【运营期 · 维护环】高频，人点改

                                回滚 = 重发上一 release（git tag）
```

## 3. 权威顺序（冲突裁决规则）

文档一定会漂移（已被 `product.contract.md` 证明过），所以钉死裁决顺序：

1. **代码实际行为**（`render.mjs` / `build.mjs` / `editor.js` 跑出来的结果）
2. **CLAUDE.md**（会话操作规范；**由用户本人维护，AI 不改动**）
3. **本蓝图**（系统完整设计与原理；蓝图侧新决策记入 [DECISIONS.md](DECISIONS.md)，最新条目优先）
4. 旧 specs 与 `对话记录-*.md`（历史，只供考古）

发现层间冲突：以高位为准，**并且必须回改低位文档**——漂移本身按 bug 处理。

## 4. 本蓝图对现行流程的破与立

用户明确授权"我的流程你也能打破"。打破了三处、新增两处，其余承重墙原样保留：

**破：**

1. **生产路收敛为一条**。原本有两条出货路（引擎 render 路 + "AI 直写 dist"的 B 路）。B 路从"逃生舱"降级为**封存**：multi-point 页已实证 B 路产物自行收敛回 render 路（2026-07-02，逐字节一致）；且 B 路破坏"可见即可编辑"的端到端闭环——编辑器写回 MD 后出货页不会自动更新，要 AI 手工重烧，这直接违背硬需求 B。特殊版式一律优先用"每页一份骨架模版"（posts 族已验证）承接；真遇到骨架模版也表达不了的页面，**须用户特批才准走 B 路**。
2. **注册表搬家的触发条件已经满足**。CLAUDE.md §2.5 约定 `REPEAT_FM_ARRAY`/`NO_STRUCT_EDIT` 搬进模版属性的时机是"做第二个页族时"——posts 页族已经存在，触发已到。列入 P2 任务（排在内容搬迁之后，避免搬迁中途动引擎）。
3. **新增建设停止线与触发式扩建表**（01 章）。v1.0 判据全绿后**冻结系统开发**，只做内容运营；任何新功能必须命中触发表，否则不建。这是对"往深做工具"惯性的制度化刹车（承接 2026-06-25 再平衡决策）。

**立（新增但不改变现有行为）：**

4. **质量门聚合**：`npm run check` 一条命令跑完 测试+build+verify:geom，挂 git pre-push 钩子；有远端后升级为 CI（06 章）。
5. **图片入库闸门**：素材落 `public/assets/img/` 前必须过压缩规范（08 章）——必须赶在批量搬迁之前生效，否则事后返工。

**不动的承重墙**（有运行证据，全部保留）：MD 真相源、引擎零名字逻辑、marker 自声明、超集模版方针、§9 七步法、编辑走 MD 坐标、改完必验。每条的原理在 02 章给了完整推导。

**巡检意外发现（P0）**：本仓库**没有任何 git remote**——包括全部内容资产、两周的决策史，唯一副本在这台 Mac 上。建议立即加一个私有远端（GitHub/Gitee/自托管皆可），这是当前系统最大的单点风险，比任何功能都优先。

## 5. 蓝图维护规则

- 新拍定的约定 → 记入 **[DECISIONS.md](DECISIONS.md)**（短，一条），再回填蓝图相应章节（长，含原理）。日志是流水，蓝图是汇编。**CLAUDE.md 由用户本人维护，AI 不改动。**
- 蓝图与现实不符 → 修蓝图（行为权威原则）。
- 每完成一个里程碑（发布线通 / 搬迁批次完成 / 冻结线达成）→ 更新 01 章清单的勾选状态。
- 本蓝图各文件**不复制** CLAUDE.md 的操作细则原文，只引用并补原理——避免双源漂移。
