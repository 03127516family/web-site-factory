# 10 · 产品化：形态与路线

> **2026-07-03 方向修正（DECISIONS ②）：当前仓库只是"内核"的参考实现 + 第一个站点（dgcrane）的资产；我们要做的是一个脱离本机的产品。** 本章定义这个产品是什么、给谁用、长什么样、分几步做到；技术架构见 [11 章](11-产品化架构.md)。01–09 章从此定位为**内核篇**——内核的规范与原理一字不变，变的是交付外壳。

---

## 1. 重新定位：内核 / 首站 / 产品

| 层 | 是什么 | 状态 |
|---|---|---|
| **内核** | MD 真相源 + marker 模版 + 确定性渲染/校验/编辑写回（`scripts/` 五件套 + `editor.js`）——[02 章](02-第一性原理.md)七条原理的实现体 | ✅ 已验证（7 页 2 族 1:1，编辑 round-trip 成立） |
| **首站** | dgcrane 中文站——产品的第一个真实用户与试验场 | 进行中（搬迁 + 发布线待做，= M0） |
| **产品** | 云端工作台：运营在浏览器里 **贴内容 → AI 生成 → 可视化审核点改 → 一键发布静态站**，全程不碰代码、不碰命令行、不依赖任何一台特定电脑 | 本章起步（M1–M3） |

**本机 npm 流程（05 章 SOP 的写法）是内核动作的"开发态"表述，不是产品交付形态。** 产品化不是推翻 01–09，而是给同一内核换外壳：每个 npm 动作都映射为产品里的一个按钮或后台任务（§4 映射表）。02 章原理全部继续成立——尤其：AI 只在写入时出现、渲染永远确定性、真相在 git、**AI 永远只出草稿**。

## 2. 产品一句话与用户故事

> **给运营的静态建站工作台：把资料变成页面，把页面点着改，把改完的一键发上线。**

用户故事（M2 完成时必须全部成立）：

1. 运营小张登录后台，点「新建产品页」，把厂里给的资料全文贴进去，填产品名和 slug，模式选"半自动"，备注"不要提价格"。
2. 几分钟后任务完成：预览链接 + 生成报告（哪些段归进了哪个模块、缺 3 张图已占位、哪两句没把握需要人看）。
3. 小张点开预览，鼠标点着改了两处文字、换了一张图——所见即所改。
4. 点「提交发布」；发布者老李过目后点「发布」；一分钟后线上更新。发布记录里能看到这版谁改了什么；上一版一键可回。
5. **全程没有任何人打开终端，没有任何环节依赖某台特定电脑。**

## 3. 角色（回收旧 spec §14 最小集）

| 角色 | 能做 | 不能做 |
|---|---|---|
| 编辑者 | 新建页面（发起生成任务）、改值、发起发布 | 直接发布 |
| 发布者 | 审核、发布、回滚 | —— |
| 管理员 | 账号、站点配置、模版版本登记（只读展示） | 在线编辑模版 HTML |
| 开发者 + agent（幕后，低频） | 新页族/模版、引擎升级——走仓库，不走后台 | —— |

红线不变：**AI 永远只产草稿，发布必经人。**

## 4. 内核动作 ↔ 产品形态映射表（本章的枢纽）

| 内核动作 | 本机形态（现在 = 开发态/逃生舱，永久保留） | 产品形态（目标） |
|---|---|---|
| 烧 MD / 烧骨架 | Claude Code 会话，用户说三件事 | 「新建页面」表单 → **生成任务**（云端 agent 跑同样的活，带自检回路） |
| 改值（L1） | `npm run edit` :8081 | **托管编辑器**（同一个 `editor.js`，套登录；保存 = 提交，作者 = 登录用户） |
| 改结构（L2） | 文本编辑 MD | 后台 MD 源码视图（validateBlocks 即时反馈），或仍走仓库 |
| 改版式（L3） | agent 改模版 + geom | **不进后台**（开发者+agent 走仓库；后台只读展示模版版本） |
| 构建 | `npm run build` | 保存/发布流程自动触发的**构建任务** |
| 验证 | `npm run check` | 任务内强制步骤，结果显示在任务面板 |
| 发布 / 回滚 | `npm run deploy / rollback`（M0 建） | **发布 / 回滚按钮** → 发布任务（原子、留 release 记录） |
| 版本 / 审计 | git 命令 | 自动化：保存=commit、发布=tag，历史界面可见 |
| 三种生成模式 | "你对 agent 说的那句话" | 新建页面表单的选项：自动 / **半自动（默认）** / 手动+约束输入（回收旧 spec §5.2——在产品形态里它们重新成为真实功能） |

## 5. 路线图 M0 → M3（每级一条完成线）

### M0 · 内核 + 首站上线（当前主线，内容不变）

- 内容：01 章 v1.0 六条判据原样（搬迁、发布线、SEO、表单、质量门、遗留清账）+ P0 git 远端。
- **完成线**：01 章 §4 全绿。dgcrane 上线是产品的第一个交付物，也是后续一切云化组件的试验场。
- 卡点：DECISIONS 待拍板 #1（托管 4 问）#2（表单）#3（托管 git）。

### M1 · 脱离本机（最小云化，几乎不写新产品代码）

- 内容：
  ① **真相层上云**：git 远端成为唯一权威，本机降级为工作副本之一；
  ② **CI 质量门**：push 即 `check`（测试+build+geom），合并即构建；
  ③ **发布任务云端化**：deploy/rollback 在 CI/runner 里跑，不再依赖任何人的电脑；
  ④ **编辑器托管**：edit-server 挂到小服务器/内网 + 登录，保存 = commit。
- **完成线**：**这台 Mac 明天丢了——资产零损失、站照发、运营照改**；运营在自己电脑的浏览器上完成一次"改值→发布"。
- 明确不做：生成上云（新建页仍由开发者+agent 会话代办）、任何数据库。

### M2 · 生成上云（AI 进产品，产品成型）

- 内容：应用服务（小后端）+ **生成 worker**（Agent SDK 无头 agent："烧 MD→自检→预览"闭环）+ 新建页面 UI（三模式）+ 页面状态与任务面板 + 页面锁。
- **完成线**：运营**不叫任何开发者**，独立完成"贴文章→预览→点改→发布"≥3 个真实页面；失败任务零污染（不碰 main、不碰线上）。
- 明确不做：多站点、在线模版管理、复杂审批流。

### M3 · 规模化（方向由 DECISIONS 待拍板 #4 决定）

- **先拍板：内部多站工具，还是对外产品？** M0–M2 两者同路，M3 分岔：
  - 内部：多站点模型（11 章 §7）+ 多语言启用（[12 章](12-修改传播与多语言同步.md)正式设计，可按需提前）+ 角色细化；
  - 对外：租户/配额/计费/合规，另立项再设计。

## 6. 与 01 章停止准则的关系（修订）

- "单一建设停止线"升级为**每个里程碑一条完成线**：完成线未过，不开下一级的新组件（防镀金）；过了，上一级组件冻结、只修不加。
- **提前必须显式**：确需跨门提前的项（如 P0 git 远端本属 M1①，因单点风险提前）必须在 DECISIONS 标注理由——允许提前，不允许默默提前。全部门禁的总表见 [14 章](14-门禁与验收体系.md)。
- 01 章触发表两项转主线：托管编辑器 → M1④；建页薄壳 → M2（不再是"薄壳"，是产品本体）。其余触发项（搜索、动态 API、多站点时机）仍由信号驱动。
- 口诀修订："做内容永远合法，**做工具必须挂在某个里程碑的清单里**"。

## 7. 产品化不改变的东西（防漂移清单）

1. 真相在 git，任何页面可从真相一键重算（02 原理 1）；
2. AI 只在写入时出现，渲染时零 AI（02 原理 2）；生成物必过 validateBlocks / geom 才见人；
3. 编辑 = 改 MD 的值（坐标系统原样）；版式不在后台改（三级模型原样）；
4. 发布原子、回滚 = 重发（02 原理 6）；
5. **后台全挂，线上静态站照常访问**——产品任何组件都不得成为访客链路的依赖；
6. AI 永远只出草稿，人是发布闸门（红线）。
