# 03 · 系统架构与数据流

> 本章是"是什么"：三层架构、仓库目录职责、三条数据流（build / edit / verify）逐步拆解、与 WordPress 的对照。原理（"为什么"）在 [02 章](02-第一性原理.md)，操作（"怎么干"）在 [05 章](05-工作流程SOP.md)。

---

## 1. 三层架构

```
┌─ 真相层（git 仓库，唯一持久资产）─────────────────────────────┐
│  src/content/*.md        每页的值（frontmatter + 正文块）        │
│  src/templates/*.html    每页族的结构与版式（marker 自声明）      │
│  src/fragments/*.html    共享 chrome（header/footer/询盘表单）   │
│  public/assets/          图片、CSS、JS 静态资产                  │
└──────────────────────────────────────────────────────────────┘
                ▼ 读                              ▲ 定点写回
┌─ 确定性机器层（scripts/，零 AI，可整体重跑）───────────────────┐
│  render.mjs       渲染器 + validateBlocks（唯一读 marker 的地方）│
│  build.mjs        页面登记 pages[] + composePage + build 入口    │
│  edit-server.mjs  :8081 可见即可编辑服务（按 page.mode 分流）     │
│  md-write.mjs     patchMarkdown——写回坐标的执行器               │
│  verify-geom.mjs  几何回归（CDP :9456）                          │
│  editor.js        编辑器前端（public/assets/js/，只读 marker）    │
└──────────────────────────────────────────────────────────────┘
                ▼ 产出
┌─ 产物层（dist/，可整删重建，永不手改）────────────────────────┐
│  dist/products/<slug>/index.html、dist/posts/<slug>/index.html │
│  dist/assets/*   （产物零 data-*，干净 HTML）                    │
└──────────────────────────────────────────────────────────────┘
                ▼ 发布线（待建，07 章）
        https://www.dgcrane.com/zh/...
```

角色层横跨其上：**agent** 写真相层、跑机器层；**人**通过编辑器改真相层的值、做最终验收；**代码**从不做判断。

## 2. 仓库目录职责表

| 路径 | 职责 | 纪律 |
|---|---|---|
| `src/content/*.md` | **真相源**：每页一份，YAML frontmatter + markdown 正文块 | 结构只许存在于 MD；规范见 [04 章](04-内容模型与模版契约.md) |
| `src/content/raw/` | 原料：内容方给的裸文章（`.txt`，posts 有子目录） | 只进不改；烧完保留（审计用） |
| `src/templates/` | 页族模版：`product-superset.html`（产品族超集）、`posts/<slug>.html`（每篇文章一份骨架）、`product.contract.md`（契约参考） | 模版=L3 版式层，改动必过 `verify:geom`；`product.html`、`overhead-cranes-for-sale.html` 为 legacy，待退役（P2） |
| `src/fragments/` | 共享 chrome：`header.html`、`footer.html`、`inquiry-form.html` | 改一处全站生效；**build 与 verify-geom 两处 compose 都要接**（踩过坑，见 06 章坑账#4） |
| `src/layouts/document.html` | 文档外壳（`<head>`、`{{SEO}}` 占位符在第 8 行附近） | SEO 注入点（08 章） |
| `public/assets/` | 图片/CSS/JS；`js/editor.js` 是编辑器前端 | 图片入库必须过闸门（08 章）；缺图按 known-leftover 规则带宽高占位 |
| `dist/` | 构建产物 | **可整删重建，永不手改**（B 路封存后此条无例外） |
| `scripts/` | 机器层五件套 + 测试（`*.test.mjs`） | 引擎铁律见 CLAUDE.md §2 |
| `docs/blueprint/` | 本蓝图 | 维护规则见 README §5 |
| 仓库根 `对话记录-*.md` | 重要会话存档 | 只追加 |

## 3. 页面登记层：`build.mjs::pages[]`

`pages[]` 是"slug → 模版 → 内容"的路由表，每条含：

- `slug`：发布路径（`products/<slug>` 或 `posts/<slug>`）
- `template`：用哪份模版（产品族指向超集；post 指向自己那份骨架）
- `type`：`product` | `post`（页面家族标记）
- `mode`：目前全部 `"render"`。**mode 的判断权归调用方**（`build()` 与 `edit-server.mjs` 各自分流），`composePage` 只专心做 render，内部无条件分支（2026-07-02 决策）——这样未来若真有非 render 页面，编辑器走"读 dist 注入"另一条路，而不是 500。

**当前登记现状（7 页，全部 `mode:"render"`）**：

| slug | type | 模版 |
|---|---|---|
| products/single-girder-eot-cranes | product | **legacy `product.html`**（2026-07-03 实况盘点纠正：尚未切超集，见 04 章台账#3，已提前排期） |
| products/overhead-cranes-for-sale | product | 超集 |
| products/free-standing-jib-cranes | product | 超集 |
| products/multi-point-suspension-cranes | product | 超集 |
| posts/32t-rail-mounted-container-gantry-crane-exported-to-russia | post | posts/同名骨架 |
| posts/gantry-cranes-for-sale | post | posts/同名骨架 |
| posts/crane-lifting-safety-training | post | posts/同名骨架 |

新增页面 = 在 `pages[]` 加一条 + 落一份 MD（+若新页族，加一份模版）。**引擎文件永不因加页而改。**

## 4. 数据流 ①：build（MD → 出货 HTML）

```
npm run build
  └─ 对 pages[] 每条：
     1. 读 src/content/<slug>.md → 解析 frontmatter + 正文块
     2. validateBlocks：每个 ## 二级标题必须带合法 <!--block:KEY-->，
        且 KEY 规范化后必须在模版出现（data-field / data-optional）
        —— 违反即抛错中止，不静默退默认
     3. render.mjs 按模版 marker 装配：
        · data-field="a.b"    → 取 frontmatter 点路径 a.b 填入
        · data-field="KEY.body" → 取 <!--block:KEY--> 块正文（mdToHtml）
        · data-repeat + data-array → 按 MD 数组克隆首个单元
        · data-optional="key" → MD 无该 key 则删整段
        · 判断只依据 marker + 内容形态（含 "<" → rich；body 含 <table> → 套 .custom_tables）
     4. composePage：套 layouts/document.html 外壳
        + 注入 fragments（{{INQUIRY_FORM}} 等）+ {{SEO}}（现为空，08 章接入）
     5. 剥离所有 data-*，写 dist/<slug>/index.html（干净产物）
```

确定性承诺：同一份真相层输入，任何机器任何时间 build，产物逐字节一致。

## 5. 数据流 ②：edit（可见即可编辑 → 定点写回 MD）

```
npm run edit  （localhost:8081）
  1. edit-server 按 page.mode 分流；render 页 = 渲染"带 marker 版"
     + 注入 window.__EDIT__（slug 等）+ editor.js
  2. 页面上每个可编辑点带三样东西：
     · 写回坐标 data-md（fm:a.b | mdhead:KEY | mdbody:KEY）
       —— 由 buildData 在"字段实际取自哪"就地登记（读哪写哪，对称防漂移）
     · 编辑类型 data-edit（text/rich/image/link）
     · 重复区上下文 data-group / data-idx（增删克隆用；data-no-add 关闭增删 UI）
  3. 用户点击 → 按类型弹对应控件 → 提交
  4. md-write.mjs::patchMarkdown 按坐标定点改写 src/content/<slug>.md
     （rich 内容经 htmlToMd 转回 markdown，与 mdToHtml 互逆，含表格↔管道表）
  5. 重渲返回 → 屏幕所见 = MD 新状态
```

编辑器前端只认 marker（`data-md/edit/group/idx`），不认任何字段名——与引擎同一条铁律。

## 6. 数据流 ③：verify:geom（版式无损证明）

```
npm run verify:geom
  1. 起 headless 浏览器（CDP 端口 9456——避开系统 Chrome/Edge 的 9222，勿杀 Edge 进程）
  2. 渲染 A=本次产物、B=基准（原静态模版，或 baseline 指定的跨模版参照）
  3. 逐元素比对几何（位置/尺寸），差异逐条报告
  4. 1:1 = 版式无损；任何差异都要么修掉、要么给出解释
```

注意：verify-geom.mjs **独立维护一份 compose()**——fragment 注入等 compose 逻辑改动必须两处同步，否则出现"假性不对齐"（坑账#4）。P2 可抽公共模块根治。

**基准策略**：
- **还原页**（对老站 1:1 重建）：基准 = 原站静态快照，逐页 geom。
- **新内容页**（老站没有的）：基准 = 本页族参照页（baseline 跨模版比对），保族内版式一致；内容正确性靠人审。

## 7. 与 WordPress 的对照（替代关系一览）

| WordPress | 本系统 | 备注 |
|---|---|---|
| wp_posts / MySQL | `src/content/*.md` + git | 人可直读，diff 即字段级差异 |
| 主题 PHP + 每次访问现场渲染 | 模版 + render.mjs **构建期**渲染 | 访客永远拿死文件 |
| wp-admin 编辑页 | `npm run edit`（:8081） | 只改值，改不坏版式 |
| 修订版本（revisions） | git log / git diff | 免费、全量、可审计 |
| 插件（表单/SEO/画廊） | fragments + build 期生成 SEO + photoswipe 静态引入 + 表单端点（待定） | 无插件生态=无插件 CVE |
| 用户/角色/权限 | 现阶段 = git 权限 | 触发表命中再议 |
| 服务器 + PHP + 数据库运维 | 无服务器，静态托管 | 攻击面≈0 |
| 主题开发者（人） | **AI agent** | 这是"80% AI 化"的主语 |

## 8. 边界与约束（架构级不变量）

1. **结构只存在于 MD**；模版固定不可在线编辑；某页多/少一段，只改 MD。
2. **`#product` 包裹关系**：从标题一直包到询盘表单才闭合（main.css 89 条 `#product` 作用域规则依赖它，提前闭合塌过两次）；`related-products` 在其外（全宽）。
3. **产物可弃**：dist 任何时刻可 `rm -rf` 后重建。若发现"重建后与之前不同"而真相层没改，即引擎 bug，按最高优先级处理。
4. **引擎零名字逻辑**：判断只靠 marker + 内容形态。遗留的声明式注册表（`REPEAT_FM_ARRAY`/`NO_STRUCT_EDIT`）搬进模版属性列入 P2（触发条件已满足——posts 是第二页族）。
5. **一条生产路**：一切页面走 render 路。B 路（AI 直写 dist）封存，启用须用户特批（README §4 破#1）。
