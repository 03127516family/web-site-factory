# 16 · 装配契约（Assembly Contract v1）——AI 组的页和代码组的页为什么能互换

> **这份是"规则本身"**：任何装配者（引擎代码、AI agent、未来任何工具）产出的页面，必须满足本契约，才能被 `render.mjs` 重渲、被 `editor.js` 编辑、被质量门验证。**契约是站点无关、页族无关的**——它就是"这套引擎能服务下一个网站"的根本原因。
> 回答用户 2026-07-03 的两个问题：①"edit.js / render.mjs 后续其他网站也能使用吧？"——能，因为它们只认本契约，不认任何站点/字段名（站点边界见 [17 章](17-引擎与站点分离.md)）；②"AI 生成的 HTML 肯定有什么规则必须符合 edit/render 吧？"——就是本契约第 E 节的**装配十律** + 第 F 节的**机器判定**。

## 0. 契约的三方与地位

```
        ┌──────────── 契约 v1（本文）────────────┐
        │                                        │
  内容方(MD)          结构方(模版/带marker HTML)      引擎方(render/editor/patch)
  只按 A 节写 MD       只按 B/C/D 节挂 marker         只按 marker+内容形态行事，
                                                   永不认名字（CLAUDE.md §2 铁律）
        ▲                    ▲
        └── 装配者（代码 or AI）是履约方：产出必须同时满足内容方与结构方规范 ──┘
```

- **权威顺序**：代码实际行为 > CLAUDE.md > 本契约。发现契约与 `render.mjs` 行为不符 → 行为权威，回改契约（漂移按 bug 处理）。
- **版本**：本文=contract@1，即现行 `render.mjs`/`editor.js`/`md-write.mjs` 行为的规范化。演进规则见 G 节。

## A. 内容方规范：MD 长什么样

一份 MD = 一个页面。结构：**YAML frontmatter + markdown 正文**，`---` 分隔。

### A1. `page:` 登记块（frontmatter 顶部，必有）

| 字段 | 必/选 | 含义 |
|---|---|---|
| `slug` | 必 | 页面路径（如 `products/xxx`），全站唯一 |
| `type` | 必 | 页族：`product` / `post` /（未来 `category` / `home` …） |
| `lang` | 必 | BCP-47（`zh-CN` / `en` …），多语言镜像树的配对键之一 |
| `title` / `description` | 必 | 页面级 SEO 元数据（L1 派生的原料） |
| `template` | 必 | 该页用哪份模版（posts 族=每篇一份骨架的路径） |
| `mode` | 选 | 默认 `render`；非 render 页（AI 直写 dist 的逃生舱页）标注于此 |
| `geomBaseline` | 选 | 几何基准（有则纳入 verify:geom） |
| `family` | 选 | 模版族@版本（如 `product-superset@1`） |

**登记即内容**：系统的页面列表由扫描 content 目录派生，**不存在第二个登记处**（F1 收敛判据，15 章）。

### A2. 数据字段（frontmatter 其余部分）

- 点路径即坐标：模版 `data-field="hero.title"` ↔ frontmatter `hero.title`。
- 重复区数据 = frontmatter 一个**对象数组**（如 `subtypes:`），单元内字段用单数相对名（`title`/`body`/`image`）。

### A3. 正文块（markdown 正文）

- 每个 `##` 二级标题**必须**带 `<!--block:KEY-->`；KEY 规范化后必须在模版出现（`data-field="KEY.body"` 或 `data-optional`）。违反 → `validateBlocks` 抛错中止（**改坏不静默**，2026-06-26 决策）。
- 块正文可含 h4/p/ul/表格（管道表格 ↔ `<table>` 由引擎互逆转换）。

### A4. 多语言配对（12 章详）

- `content/zh/<slug>.md` ↔ `content/en/<slug>.md`：**路径镜像即逻辑配对**，不建配对表。
- 目标语言 MD 的 frontmatter 带 `i18n.source_commit`（译自源语言哪个 commit），是 ⑦ 字段级增量同步的锚点。

## B. 结构方规范：marker 词汇表（封闭集，contract@1）

模版/带 marker 的 HTML 只许用这些声明，引擎只读这些：

| 声明 | 含义 | 成对规则 |
|---|---|---|
| `data-field="点路径"` | 值槽，数据取 MD 该路径 | 必配 `data-edit` |
| `data-edit="text\|rich\|image\|link"` | 该槽如何编辑/填 | 依附 `data-field` |
| `data-repeat="名"` | 重复区，按 MD 数组克隆首个单元 | 目标容器配 `data-array="md.路径"` |
| `data-optional="key"` | MD 无该 key → 删整段 | 独立 |
| `data-required` | 该点缺 MD 数据 → **报错中止**（不许退模版占位）。挂 `data-field` → 值必须解析到非空；挂 `data-repeat` 容器 → 数组必须非空 | 与 `data-optional` 互为反义 |
| `data-no-add` | 该重复区不显示增删 UI | 依附 `data-repeat` |
| `<!--block:KEY-->`（MD 侧） | 长正文块 | 对模版 `data-field="KEY.body"` |

**运行时坐标（引擎生成，不许手写）**：编辑模式下引擎为每个槽产出 `data-md="fm:…/mdhead:…/mdbody:…"` + `data-group/data-idx`——这是 editor.js 与 patchMarkdown 之间的写回坐标，由 `buildData` 在"字段实际取自哪"就地产出。装配者**不得**在模版里手写 `data-md`；生产构建剥除全部 `data-*`。

**引擎的判断只许来自两类信息**：marker（上表）+ 内容形态（值含 `<`→rich、body 含 `<table>`→套表格样式、多段→rich）。**永远禁止**按字段名/产品名/站点名开 if 分支。

## C. 命名铁律（接线，非审美）

**模版里的名 = MD 里的路径，一字不差。** `data-field="hero.title"` 就去 MD 取 `hero.title`；`data-array="md.subtypes"` 就对 frontmatter `subtypes:`。跨页族复用的名照搬不另起（`hero` / `inquiry_form` / `related_products` / `breadcrumb.trail`）。习惯：语义英文小写、点分层、重复区复数名。

## D. 结构硬约束（违反会实际坏掉的物理规则）

| # | 约束 | 违反的后果（都实际踩过） |
|---|---|---|
| D1 | 多段富文本用 `<div data-field="X.body">`，**禁 `<p data-field>`** | 浏览器把 `<p>` 里的块级内容拆成兄弟节点 → 只有首段可编辑 |
| D2 | 重复区只保留第 1 个单元当克隆模子 | 多留 → 克隆时内容翻倍 |
| D3 | chrome（header/nav/footer/photoswipe/询盘表单）从 `fragments/` 逐字注入，不重写 | 手抄 → 5 份拷贝漂移（表单已踩，2026-07-01 决策治过） |
| D4 | **站点声明的包裹容器必须完整闭合**（dgcrane：`#product` 从标题包到询盘表单；此规则属**站点层配置**，见 17 章，不是引擎知识） | 提前闭合 → 89 条作用域 CSS 全失效，整片塌（塌过两次） |
| D5 | 缺图按 known-leftover：`<img>` 带 `width/height` | 不带 → 图 404 版面塌，geom 过不了 |
| D6 | `htmlToMd ↔ mdToHtml` 必须互逆（含表格） | 不互逆 → 编辑一次内容变形一次 |

## E. 装配十律——AI（或任何工具）组一个页面必须遵守的全部规则

这就是"AI 生成的 HTML 要符合什么规则才能被 edit/render 使用"的正面回答。**十条，缺一不可**：

1. **MD 先行**：页面全部内容先落 MD 且 `validateBlocks` 过。HTML 里不许存在 MD 之外的正文内容（chrome 除外）——否则该页脱离真相源，编辑器改 MD 出货页不会跟。
2. **值必挂槽**：每个可变值（文字/图/链接）包 marker，名=MD 路径一字不差（C 节）。没挂槽的值 = 编辑器看不见的值 = 不许存在。
3. **富文本载体守 D1**：多段正文一律 `<div data-field="KEY.body">` + MD `## 块`。
4. **重复结构守 B+D2**：同构出现 N 次的内容 → `data-repeat` + `data-array`，MD 落数组，HTML 只留模子。
5. **可省段挂 `data-optional`，必填点挂 `data-required`**（互为反义）：可省段=本页有、同族别页可能没有（缺→删段）；必填点=占位符本身非内容、退占位即错的值（如 `breadcrumb.current`/`trail`、`title`），缺→**报错中止**。判据：模版占位是"真能上线的默认"(如 shared 品牌语、fallback 图) → 不挂；占位是"假文字/骗人的默认"(如 `当前页`) → 挂 `data-required`。**AI 烧 MD 必须满足模版声明的所有 `data-required`**（漏了 build 直接红，非静默出占位——1.2 走查落地）。
6. **chrome 逐字复用 fragments**（D3），语言切换/表单 action 里的页面路径替换为本页 slug。
7. **守站点包裹规则**（D4，从站点配置读，不猜）。
8. **同形律（核心）**：引擎按同一份 MD + 同一份模版重渲，必须得到同构 DOM（理想=逐字节一致）。这是"AI 组的页引擎能接管、编辑器能编辑"的判据——multi-point 页已实证（AI 产物与 render 输出逐字节收敛，2026-07-02）。
9. **缺料按 known-leftover**（D5），不臆造内容补位。
10. **禁止要求引擎开后门**：页面表达不了的结构，先按 G 节走契约演进（加 marker、升版本），**不许**让引擎为某个名字加特判——那是全系统腐烂的起点（CLAUDE.md §2.1）。

**推论（两路合流的真相）**："AI 组装"的合法落地形态就是 **AI 设计骨架（模版）+ 值走 MD**：
- 新页族 → AI 按 §9 七步法造一份自声明模版（一次），之后全族走引擎；
- 一次性特殊版式 → AI 造"每页一份骨架模版"（posts 族模式），仍由引擎填值；
- AI 直写 dist 成品 HTML = 逃生舱，须用户特批，且仍守十律（守了十律的页迟早收敛回引擎路，multi-point 已证明）。

即：**AI 负责"结构的创作"，引擎负责"值的装配"——两路产物同构，所以 ③SEO ④发布 ⑥编辑 ⑦翻译全都不关心页面是谁组的。**

## F. 合规判定（机器可验，不靠自觉）

一个页面"符合契约"不是声称出来的，是四道检查跑出来的：

| # | 检查 | 工具 | 验什么 |
|---|---|---|---|
| C1 | 块校验 | `validateBlocks`（build/verify 共用） | MD 每个 `##` 带合法 block、每个 KEY 模版有槽（十律 1） |
| C2 | 坐标可达 | 编辑模式渲染 + round-trip 单测 | 每个 `data-field` 得到 `data-md` 写回坐标；`htmlToMd(mdToHtml(x))=x`（十律 2、D6） |
| C3 | 同形/收敛 | 引擎重渲 vs 交付 HTML 结构比对（B 路页专用） | 十律 8：引擎能从 MD 单独重算出该页 |
| C4 | 几何 1:1 | `verify:geom`（CDP，逐元素包围盒） | 版面无损（D4/D5 的兜底） |

**接入点**：C1 已在每次 build 强制；C2 在单测 **+ `scripts/edit-probe.mjs` 全坐标回归门**（455 坐标真实写回→重渲→验值，纯内存不写文件，进 `npm run check`）；C4 在 `npm run check` + pre-push + CI；C3 在 B 路页交付时执行。云端形态下同一套检查跑在 publish Lambda 里——**不合规的页发不出去**。
- **引擎字符串入口（2026-07-03，⑲）**：`render.mjs` 提供 `renderBodyFromString(template, mdString, opts)`（纯函数、不碰 fs），是 C1–C4 在**云端**跑（edit-save/render-page/publish Lambda 拿到的 MD 是字符串）以及 edit-probe 纯内存跑的共同底座；`renderBodyFromMarkdown(path)` = readFile + 委托它，dist 逐字节不变。

## G. 契约版本化（引擎不动，契约演进）

- **加能力 = 加 marker（minor）**：新 marker 必须是"旧模版不写它则行为不变"的增量（如未来 `data-when` 条件段）。旧站旧模版零迁移。
- **改语义 = contract@2（major）**：必须给迁移脚本 + 全站 geom 复验，模版 `family@版本` 是迁移单位。
- **谁提案**：装配中发现表达不了的结构 → 记 DECISIONS 待拍板 → 拍定后引擎一次实现 → 所有站受益。**顺序永远是"契约先行，引擎跟随"**，不许某站先私改引擎。
- contract@1 已知待收敛项（不阻塞使用，登记在案）：`REPEAT_FM_ARRAY`/`NO_STRUCT_EDIT` 两张声明式注册表尚在 `render.mjs`（render.mjs:35/42），归宿是模版属性（`data-array` 已有、`data-no-add` 已有，搬迁=纯机械），列在 17 章纯化清单。

## H. 现状符合度（2026-07-03）

- 引擎三件（render/editor/md-write）**已按本契约行事**——契约是从它们的实际行为规范化出来的，不是空想。
- 7 个页面全部 `mode:render`、C1/C2/C4 在质量门覆盖（geom 暂 2/7 页有基准，1.0b 补齐）。
- posts 族 = "AI 设计骨架 + 引擎填值"的活证据；multi-point 页 = 同形律的逐字节实证。
