# 04 · 内容模型与模版契约

> 本章定义真相层的两半：**MD 怎么写**（内容模型）与**模版怎么造**（契约与页族方法论）。操作细则以 CLAUDE.md §2/§5/§9 为会话权威，本章补齐语义与原理，并维护结构债务台账。

---

## 1. MD 文件解剖

每页一份 `src/content/<slug>.md`，两段式：

```markdown
---                        ← YAML frontmatter：所有"单值"与"数组"
slug: products/xxx
template: product-superset
hero:
  title: 产品名
  image: xxx.jpg
subtypes:                  ← 数组 = 模版重复区的数据源
  - title: 子型号A
    image: a.jpg
---
## 概述 <!--block:overview-->      ← 正文块：所有"长富文本"
多段落、列表、**加粗**、管道表格都可以……

## 主要特点 <!--block:main_features-->
……
```

**三类数据、三种去处**（与 01 章三级编辑模型的 L1 对应）：

| 数据形态 | 放哪 | 模版怎么取 | 编辑坐标 |
|---|---|---|---|
| 单值（标题/图/链接） | frontmatter 点路径 `a.b` | `data-field="a.b"` | `fm:a.b` |
| 长富文本（多段/列表/表格） | 正文 `## 标题 <!--block:KEY-->` | `data-field="KEY.body"`（自动映射） | `mdhead:KEY` / `mdbody:KEY` |
| 同构重复（子型号/FAQ/案例/组件） | frontmatter 数组 | `data-repeat` + `data-array="md.数组路径"` | 组内单数相对名 + `data-idx` |

**validateBlocks 两条硬规则**（build/verify 共用，违反即中止）：
1. 每个 `^##` 二级标题必须带合法 `<!--block:KEY-->`；
2. 每个 KEY 规范化后必须能在模版找到着落（`data-field` 或 `data-optional`）。

## 2. marker 词汇表（模版的全部合法词汇）

模版是"自报结构的 HTML"。引擎只读下面这些词，**不读任何具体名字**：

| marker | 语义 | 备注 |
|---|---|---|
| `data-field="点路径"` | 内容点，值取 MD 该路径 | `KEY.body` 自动对 `<!--block:KEY-->` |
| `data-edit="text\|rich\|image\|link"` | 该点的编辑/填充方式 | 决定编辑器控件与序列化 |
| `data-repeat="名"` | 重复区，克隆首个单元 | 配对 `data-array` 使用 |
| `data-array="md.路径"` | 重复区的数据源数组 | 目标态：全部自声明（见 §6 债#4） |
| `data-optional="key"` | MD 无该 key → 删整段 | 超集裁剪的实现 |
| `data-no-add` | 该重复区不显示增删 UI | 如导航类固定重复 |
| `<!--block:KEY-->` ↔ `data-field="KEY.body"` | 长正文块与槽的配对 | KEY 任意、自动映射 |

**硬约束（血的教训）**：多段富文本槽必须用 `<div data-field="X.body">`，禁用 `<p data-field>`——`<p>` 装不下多个 `<p>`，浏览器解析时拆成兄弟节点，只有首段可编辑（坑账#3）。

**现状注记（2026-07-03 实况盘点，DECISIONS ⑬）**：上表是**目标态词汇表**；现行超集模版实际只用了 `data-field`(145)/`data-repeat`(9)/`data-optional`(17)——**`data-array` 与 `data-edit` 已定义未启用**：repeat 的数组绑定暂靠引擎注册表 `REPEAT_FM_ARRAY`，编辑类型靠内容形态推断（这正是台账#4"注册表搬家"要还的债，P2）。读模版时以此为准，别按词汇表全集去找。

**扩展形态注记**（2026-07-03 外贸站审计补，不引入新 marker）：
- **视频**（产品/工厂视频）：嵌入代码（iframe/video）属**版式骨架**（L3，烧进模版）；视频地址、封面图是**值**（`data-edit="link"` / `"image"`）——与图文同一套三级模型；
- **附件下载**（PDF 产品目录/规格书）：下载按钮 = 链接字段（`data-edit="link"`），文件本体走附件规范（08 章 §3）落 `public/assets/files/`。

## 3. 命名铁律：接线，不是审美

**模版里的名字 = MD 里的路径，一字不差。** `data-field="hero.title"` 就去 MD 取 `hero.title`；`data-array="md.subtypes"` 就对 frontmatter `subtypes:` 数组。名字的唯一职能是**接线**；起名习惯（语义英文小写、点分层、重复区复数、单元内字段用单数相对名 `title`/`body`/`image`）是为了让接线可读，不改变其职能。

**跨页族复用的名字照搬，不另起**：`hero`、`inquiry_form`、`related_products`、`breadcrumb.trail`——同名即同物，编辑器与引擎因此天然通用。

## 4. 页族方法论：真实页 → 模版的七步法

（操作权威 = CLAUDE.md §9；此处列步骤并**补每步的存在理由**。）

| 步 | 做什么 | 为什么存在 |
|---|---|---|
| ① 切块 | 真实页正文从上到下切段，每段单独判定 | 判定单位错了后面全错；段是版式的原子 |
| ② 判形 | 每段归入 4 形态之一（单值/长正文/重复/可选） | 4 形态穷尽任何页面 → 保证零特判（原理 3） |
| ③ 命名 | 同名接线；跨页族复用名照搬 | 名字=接线；复用名让引擎与编辑器零新知识 |
| ④ 抽模子 | 重复区只留第 1 个单元当克隆模子 | 模子唯一，数据驱动份数——结构进 MD 不进模版 |
| ⑤ 复 chrome | head/header/nav/footer/photoswipe 从现成产物页逐字复制 | chrome 是共享外壳，重写=引入漂移；逐字复制天然 1:1 |
| ⑥ 守硬约束 | `<div data-field>` 不用 `<p>`；`#product` 包到询盘才闭合 | 两个都塌过（坑账#1/#3） |
| ⑦ 验 | 落基准 MD → validateBlocks 过 → build → verify:geom 1:1 | 没有验证的模版等于没造完（原理 5） |

**形态 → marker 速查**：一个标题/图/链接 → 单值（`data-field`+`data-edit`）；连续几段说明 → 长正文（`div data-field="KEY.body"`+`<!--block:KEY-->`）；同结构 N 次 → 重复（`data-repeat`+`data-array`）；本页有别页可能没有 → 可选（`data-optional`）。

**此规则页族无关**：product / post / category / 未来任何页族一字不改。谁觉得"这个页族要特殊切法"，谁就在重新引入被原理 3 禁止的 O(N) 逻辑。

## 5. 两类页族形态

### 5.1 schema 型页族（product、未来 category）：一份超集模版 + 按 MD 裁剪

- 同一风格只养**一份超集模版**（现：`product-superset.html`，单梁 12 段 + overhead 独有 5 段 = 17 段，可省段全带 `data-optional`）。
- 加同风格产品 = 只写一份 MD，零新模版；某产品少哪段，MD 不写那个 key 即被裁掉。
- 真出现**另一种风格**才另起超集。判据是风格（视觉/布局体系），不是内容多少。
- category 页族（品类页：子型号各自带规格表+FAQ+案例）是 §4 七步法的下一个试金石，做它时**先按规则再动手**。

### 5.2 骨架型页族（post 文章/案例）：每篇一份骨架模版

文章的本质区别：正文是**自由散文 + 逐图自定义排版**，没有固定 schema。但"可见即可编辑"是硬需求。解（原理 4 推论 2）：

- **布局 = AI 烧一次的死骨架**，存 `src/templates/posts/<slug>.html`，带 marker 槽；要改版式 = 重烧骨架（L3）。
- **值 = 活在 MD**：长文段 → `## 块`；标题/图文件名 → frontmatter `body.<语义id>`（多图 `body.<段>_img<n>`）；排版由骨架里父容器 class（`fig-full`/`fig-2col`/`fig-grid`）决定，逐段自由。
- `pages[]` 把该 slug 指向自己那份骨架 → 改值后 `npm run build` **自动重渲**，编辑体验与产品页完全一致。
- TOC（左栏目录）由页内 JS 扫真实 h2/h3 自动生成，属 chrome，零引擎介入。

这套"每篇一份骨架"就是旧 spec 想要的"AI 自由排版每一页"的**可编辑版本**——自由度一点没少，只是被冻进了骨架层。

## 6. 结构债务台账

| # | 债 | 影响 | 收敛动作 | 级 |
|---|---|---|---|---|
| 1 | `components`/`crane-types` 双处结构（frontmatter `*_images` + 正文 `###` 按 index 对应） | 两处要人工保持同步，易错 | 收敛为单处（数组内含 image 字段），改模版 `data-array` 对齐，全族重渲+geom | P2 |
| 2 | `breadcrumb.trail` 未 data 化（超集里硬编码单梁面包屑，显示「Eot Cranes」） | 非单梁产品面包屑是错的 | trail 进 MD（数组），模版挂 `data-repeat`；与 08 章 BreadcrumbList JSON-LD 一并做 | **P1（随 SEO）** |
| 3 | legacy `product.html` **仍在役**——single-girder 页在用（2026-07-03 实况盘点纠正，此前蓝图误记全部产品页已用超集）；`overhead-cranes-for-sale.html` 实为 **geom 基准素材**、非服役模版，保留不删 | 双模版并存：每次改产品版式要改两份，批量搬迁前是隐患 | single-girder 切超集 → geom 1:1 → 删 `product.html` | **P1.5（已提前至 B1 搬迁之前）** |
| 4 | `REPEAT_FM_ARRAY`/`NO_STRUCT_EDIT` 名字注册表还在 render.mjs | 违反"结构自声明"的最后残留 | 搬进模版 `data-array`/`data-no-add`；**触发条件已满足**（posts=第二页族） | P2 |
| 5 | `product.contract.md` 会漂移 | 契约当权威会误导 | 短期：文首注明"行为权威"；长期：从模版 marker **派生**契约（`npm run contract`） | P2/P3 |
| 6 | 个别素材缺失（如 overhead 组件 `Crane-electric-control-bo.jpg`，原站亦缺） | 页面有占位框 | 维持 known-leftover（带宽高不破几何）；季检清点补图 | 持续 |
| 7 | 导航菜单未数据化（header fragment 里硬编码；新增页面/品类后要手改 fragment 才有入口） | 新页上线容易忘挂菜单，页面成"孤岛" | 短期：SOP-1/2/3 增加"核对导航"一步（已加）；长期（M2+）：菜单项由 `pages[]`/站点配置生成进 fragment | P2（短期步骤立即生效） |
| 8 | 超集 related-products 区残留**旧 spec 词汇**（`data-template="related-products@1"`、`data-dynamic`、`data-block-id`）——实际是构建期静态渲染（MD `related_products` 数据），产物已剥 data-*，无害但误导读模版的人 | 会被误读为"动态 API 模块" | 随面包屑/SEO 改造顺手清掉旧属性 | P1（随 SEO） |

**债务纪律**：新债只许进这张表，不许散落在对话里；每条债必须带收敛动作与优先级；P2 债统一排在搬迁主线之后（01 章 §8），避免中途动引擎。

## 7. 契约文档策略

- `product.contract.md` 保留为**设计意图参考**；最终权威 = `render.mjs` 实际行为 + 现行 `single-girder-eot-cranes.md`（活样例）。
- 长期方向（P3，可不做）：`npm run contract` 扫模版 marker 自动生成字段清单——文档派生化（原理 7），手写契约只留"为什么"。

## 8. 站点级内容（`site.md`）——chrome 的高频值也要可见即可编辑

**问题**（2026-07-03 外贸站审计发现）：公司电话、邮箱、地址、社媒链接、备案号这些值躺在 header/footer fragment 里——按原设计改它们 = 改 fragment（L3，找 agent）。但它们明明是**值**（L1）：电话换号这种事，运营应该点一下就改掉。

**设计**（实施排 M1–M2）：
- 新增**站点级内容文件** `src/content/site.md`：frontmatter 存全局值（`company.phone` / `company.email` / `company.address` / `social.*` / `icp` …）。
- fragments 里这些位置挂 `data-field="site.*"`——compose 注入 fragment 时按 marker 填值（引擎机制复用，零新概念）；编辑器里它们与页面字段一样可点改，写回 `site.md`。
- 传播语义：改 `site.md` = **全站重渲**（12 章矩阵第九行）；多语言下每语言一份 `site.md`（号码通常共享、文案各语言）。
- 边界：`site.md` 只放**值**；导航结构与 fragment 版式仍属 L3。
