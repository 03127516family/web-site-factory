# 06 · 验证体系与坑账

> 前半是**验证怎么组织**（金字塔、自动化、回归排查），后半是**已经踩过的 12 个坑**（现象/根因/防线）与**风险登记册**。坑账是本系统最贵的资产之一——每条防线背后都是真实事故。

---

## 1. 验证金字塔

| 层 | 工具 | 保什么 | 失败行为 |
|---|---|---|---|
| 1 MD 合法 | `validateBlocks`（render.mjs 内，build/verify 共用） | `## 块`注释合法、KEY 在模版有着落 | **抛错中止**，报具体块 |
| 2 装配成功 | `npm run build` | 模版+MD+fragments 能组装出完整 HTML | 抛错中止 |
| 3 版式无损 | `npm run verify:geom` | 与基准逐元素几何 1:1 | 差异逐条列出，必须清零或逐条解释 |
| 4 单元逻辑 | `node --test scripts/*.test.mjs`（md-write.test / build.test） | 写回函数、compose 路由等纯逻辑 | 测试失败 |
| 5 内容正确 | 人工预览（serve :8080 / edit :8081） | 事实、语义、图文对应 | 人说不行就不行 |

**原则**（[02 章](02-第一性原理.md)原理 5）：每层失败必须中止并报位置，**绝不静默退默认**。"改坏不报错"比"改坏"危险一个数量级。

**基准策略**：还原页 → 基准=原站快照，逐页 geom；新内容页 → 基准=族内参照页（baseline 跨模版），保版式一致，内容靠人审。geom **不保证**文案对错——所以第 5 层永不可省，AI 只出草稿、人是发布闸门。

**视口策略**（2026-07-03 审计补，DECISIONS ⑧）：原站是响应式站——geom 与人工预览都必须**双视口**（桌面 + 移动宽度各验一遍），单视口验证会漏移动端塌版；性能侧的移动模拟已在 08 章预算内。

**基准生命周期——"祝圣"流程（2026-07-03 走查 F5 补，15 章）**：基准不是永恒的，**改版式 = 故意不 1:1**，必须回答"新基准从哪来"。流程：改模版 → 全族重渲 → 人审通过 → 把新产出快照**显式提交为新基准**（提交信息注明"基准更新：〈原因〉"）→ 此后 geom 对新基准验。AI 设计的新页（posts 等无原站参照的）以"人审通过的首次渲染"为初代基准。基准更新必须独立成提交、带理由——防止"顺手把验证标准改成自己的输出"这种自我欺骗。

## 2. 质量门自动化（P0）

**现状**：各项检查全靠手动记得跑。**目标**：忘了也会被拦住。

1. **聚合命令**（加进 package.json）：
   ```json
   "check": "node --test scripts/ && node scripts/build.mjs && node --experimental-websocket scripts/verify-geom.mjs"
   ```
2. **git pre-push 钩子**：推送前自动 `npm run check`；紧急绕过用 `git push --no-verify`（留痕迹的显式动作）。
3. **有远端后升级 CI**（GitHub Actions / Gitee Go）：PR 上跑同一条 `npm run check`——注意 CI 里 geom 需要无头 Chrome，装 chromium 依赖即可；装不上时 CI 先跑 1/2/4 层，geom 留在钩子层。
4. **发布线建成后**：`deploy` 脚本第一步强制 `check`，绿了才继续（07 章）。
5. **构建环境钉死**（可重现性的地基，2026-07-03 审计补）：Node 版本 pin（`engines` / `.nvmrc`）、`package-lock.json` 入库、产品期 worker 用版本化容器镜像——"同输入任何机器产物逐字节一致"（03 章 §4 承诺）依赖工具链被钉死；CI 可加"双跑 diff"抽检（同输入连 build 两次比对）把确定性承诺变成被验证的事实。

## 3. 回归排查流程（geom 不 1:1 时）

1. 看差异报告定位元素 → 判断三类成因：**内容变了**（MD 改动，预期内？）/ **模版变了**（影响面=全族，逐页看）/ **引擎变了**（最危险，全站回归）。
2. 引擎类差异：先 `git diff scripts/` 找最近改动；用二分法（git stash / checkout 单文件）锁定。
3. 修复后全族重跑 geom，不许只验出问题那页。
4. 若结论是"基准本身错了"（比如原站快照更新过），更新基准要走显式提交并在提交信息里说明——基准漂移等于验证失效。

## 4. 坑账（已踩过的坑，全部真实发生）

| # | 坑（现象） | 根因 | 防线（现状） |
|---|---|---|---|
| 1 | `#product` 提前闭合，整片版面塌掉（**发生过两次**） | main.css 有 89 条 `#product xxx` 作用域规则，包裹关系从标题必须一直包到询盘表单 | 铁律进 CLAUDE.md §7 + geom 兜底；造模版第⑥步专项自检 |
| 2 | 正文整段悄悄失效，build 不报错 | 编辑器全局 markdown 格式化把 `<!--block:KEY-->` 改写成链接 `[!--block--](...)`，渲染退默认 | **validateBlocks**（编辑器无关的兜底，违反即中止）+ `.vscode` 关 formatOnSave（辅助） |
| 3 | 富文本只有首段可编辑 | 多段内容塞进 `<p data-field>`——`<p>` 装不下块级子元素，浏览器拆成兄弟节点 | 硬约束：长正文一律 `<div data-field="KEY.body">`（CLAUDE.md §2.4） |
| 4 | A/B 几何"假性不对齐" | `build.mjs` 与 `verify-geom.mjs` **各自维护一份 compose()**，fragment 注入（`{{INQUIRY_FORM}}`）改了一处忘另一处 | 已知坑入档；改 compose 必须两处同步；P2 根治=抽公共模块 |
| 5 | AI 手写出货页与 MD 渐行渐远的风险 | B 路（AI 直写 dist）编辑后需人肉重烧对齐 | multi-point 已实证收敛回 render 路（2026-07-02 逐字节一致）→ **B 路封存**，一条生产路 |
| 6 | 契约文档说的和引擎做的不一样 | 手写文档必然漂移 | 权威顺序钉死（README §3）：行为 > 决策日志 > 蓝图 > 历史；长期文档派生化 |
| 7 | 调试时把系统浏览器进程杀了 | CDP 默认 9222 与常驻 Chrome/Edge 冲突 | 固定用 **9456**；铁律：勿杀 Edge 进程 |
| 8 | 页面 LCP 被拖垮 | 素材原图 3–4MB/张直接落盘（crane-lifting-safety-training 一批图） | **图片闸门**（SOP-6 / 08 章）：先压缩再入库；必须先于批量搬迁生效 |
| 9 | 表单填完点发送，什么都没发生 | 老站 WPForms 静态快照：`<form>` 无 action、无 JS 提交（`713`/`780` 两个表单；订阅表单 action 里还带着抓取时的 Google 追踪参数） | 已抽成共享 fragment 统一字段集；**后端方案待拍板**（07 章）；教训：迁移时逐个功能验真，别信"页面长得对" |
| 10 | 面包屑显示「Eot Cranes」而非「桥式起重机」 | 超集里 trail 硬编码单梁 + 用的是 Google 2020 起不认的 Data-Vocabulary RDFa | 债务台账#2：trail MD 化 + BreadcrumbList JSON-LD，随 SEO 一并做（P1） |
| 11 | 组件/类型区两处数据要人工同步 | `components`/`crane-types` 双处结构（frontmatter `*_images` + 正文 `###` 同 index） | 债务台账#1，P2 收敛单处 |
| 12 | 全站没有任何 SEO head | `{{SEO}}` 占位符恒被替换成空字符串 | 08 章逐项接入（base URL 已拍板，已解锁） |

**坑账纪律**：新坑必须记进本表（现象/根因/防线三段齐全）再关闭事故；防线优先做在"编辑器/人无关"的校验层。
