# 17 · 引擎与站点分离——dgcrane 成了，下一个站怎么复用

> 回答用户 2026-07-03 的判断："edit.js / render.mjs 不只是实现这个网站，后续其他网站也能使用吧？"——**对，而且这是可验证的承诺，不是口号**。本章给出：什么是引擎（跨站共享、永不动）、什么是站点（每站一份）、现在引擎里还残留哪些站点杂质（有据可查的纯化清单）、以及"从零起第二个站"的完整剧本。

## 0. 一条可机器验证的判据

> **起第二个站的那个 PR 里，引擎目录的 diff 必须为空。**

做到这条，"能复用"就不是形容词。做不到，就说明引擎里混进了站点知识——按 bug 处理。

## 1. 四层切分：谁属于引擎，谁属于站点

| 层 | 内容 | 份数 | 变更频率 |
|---|---|---|---|
| **引擎层**（跨站共享） | `render.mjs`、`editor.js`、`md-write.mjs`（patchMarkdown）、`validateBlocks`、build 装配机（compose/loadPages/seoHead/sitemapXml）、`verify-geom.mjs`、edit/serve 服务器、（未来）9 个 Lambda 载荷 | **永远 1 份** | 只随契约版本动 |
| **契约层** | [16 章](16-装配契约.md) marker 词汇表 + 装配十律 + 合规判定 | 1 份（版本化） | 极低频 |
| **站点层**（每站一份） | `site.config`、`templates/`（页族模版+每篇骨架）、`fragments/`（chrome：header/footer/表单）、`content/<lang>/*.md`、静态资产、geom 基准、CSS | 每站 1 份 | 站点自己的节奏 |
| **运行层**（多站共用基础设施，按前缀隔离） | S3 三平面里的 `<site>/` 前缀、CloudFront 行为、Lambda（同一套函数，参数带 site）、管理 SPA（站点切换器） | 1 套基础设施 × N 站前缀 | 随站点增删 |

**判定口诀**：含站点名/域名/字段名/中文文案的东西 → 站点层；只认 marker 和内容形态的东西 → 引擎层。

## 2. `site.config` 设计（站点层的"登记块"，与页面 `page:` 块同构思想）

每站一份 `sites/<site>/site.config.json`，引擎启动时读它，**引擎代码里从此不出现任何站点常量**：

```jsonc
{
  "site": "dgcrane",
  "langs": ["zh-CN"],                          // 未来 ["zh-CN","en"]
  "baseUrl": { "zh-CN": "https://www.dgcrane.com/zh/" },   // 今在 build.mjs:22 硬编码 → 搬这
  "homeLabel": { "zh-CN": "首页" },             // JSON-LD 面包屑首项，今在 build.mjs:73 硬编码 → 搬这
  "scopeContainers": ["#product"],             // 契约 D4 的站点包裹规则：装配者读这里，不靠记忆
  "formEndpoint": "MOCK",                       // 1.4 的 INQUIRY_ENDPOINT 单点常量归宿
  "imageBudget": { "maxKB": 300, "heroMaxKB": 500 },   // 图片闸门参数（08 章）
  "analytics": null                             // 站点脚本白名单
}
```

原则同 F1：**站点的一切登记只在这一处**，build/edit/verify/Lambda 全从这派生，不存在第二份站点常量表。

## 3. 引擎纯化清单（现存杂质，逐条有出处、有归宿、有时机）

2026-07-03 grep 实测，引擎里现存的全部站点/名字杂质就这 5 处：

| # | 杂质 | 出处 | 归宿 | 时机 |
|---|---|---|---|---|
| P-1 | `SITE_BASE`/`ASSET_BASE` 硬编码 dgcrane 域名 | `build.mjs:22-23` | `site.config.baseUrl` | 第二站启动前（或 v1.0 冻结后），一次搬完 |
| P-2 | JSON-LD 面包屑首项写死中文"首页" | `build.mjs:73` | `site.config.homeLabel[lang]` | 同上（做 `/en` 时本来就绕不过） |
| P-3 | `REPEAT_FM_ARRAY` 名字注册表 | `render.mjs:42` | 模版属性 `data-array`（marker 已存在，搬迁纯机械） | CLAUDE.md §2.5 约定的触发条件（第二页族=posts）**已满足**，列 P2 队列，搬迁完成后引擎零名字表 |
| P-4 | `NO_STRUCT_EDIT` 名字注册表 | `render.mjs:35` | 模版属性 `data-no-add`（同上） | 同 P-3 |
| P-5 | 面包屑 trail 硬编码单梁文案 | 超集模版（站点层文件，但属"该数据化未数据化"） | `breadcrumb.trail` 数据化（执行队列 1.2） | 阶段 1 进行中 |

**结论**：杂质全部是**声明式配置放错了位置**，没有一处是逻辑分支——引擎判断逻辑本身已经干净（零 `if 字段名`）。纯化 = 搬家，不是重写；全程有 `verify:geom` + 逐字节比对兜底（1.0 已示范过"零行为变化的数学证明"怎么做）。

## 4. 目标目录布局（多站形态）与迁移时机

```
（现状·单站）                      （目标·多站）
scripts/          ──────────▶     engine/            ← 跨站共享，版本化（contract@1）
public/assets/js/editor.js  ─▶    engine/editor.js
src/templates|fragments|content ▶ sites/dgcrane/{site.config, templates/, fragments/, content/zh-CN/, assets/, baselines/}
                                  sites/<下个站>/…    ← 第二站只加这个目录
```

**迁移时机拍定**：**不在 dgcrane 搬迁中途动**（避免双重变量）。触发条件二选一，先到先触发：① dgcrane v1.0 清单全绿冻结后；② 第二个站真的启动时。迁移本身是纯移动 + 路径改配置，验收 = 7/7 页逐字节一致（同 1.0 手法）。

## 5. 从零起第二个站：完整剧本（9 步，标注谁干、引擎动不动）

| 步 | 做什么 | 谁干 | 引擎改动 |
|---|---|---|---|
| N1 | 建 `sites/<site>/site.config.json`（域名/语言/包裹规则/表单端点/图片预算） | 用户给料，AI 落盘 | **0** |
| N2 | chrome 采集或设计：header/footer/表单 → `fragments/`（新站新风格=AI 设计；克隆旧站=逐字采集） | AI | **0** |
| N3 | 页族模版：按 §9 七步法（切块→判形→命名→抽模子→复 chrome→守硬约束→验）造超集模版，一族一份 | AI | **0**（契约不够表达才走 16 章 G 节演进） |
| N4 | 首批内容烧制：裸文章 → MD（带 `page:` 登记 + L2 SEO） | AI | **0** |
| N5 | 基准祝圣：首页面 geom 基准冻结（06 章祝圣流程） | AI 产、用户过目 | **0** |
| N6 | 质量门就位：该站进 `npm run check` / CI（登记派生，自动纳入） | 自动 | **0** |
| N7 | 发布线：S3 三平面挂 `<site>/` 前缀 + CloudFront 行为 + DNS | AI 脚本、用户授权 | **0**（Lambda 参数带 site） |
| N8 | 管理软件：站点切换器里出现新站（站点列表从 `sites/` 目录派生，同 F1 思想） | 自动 | **0** |
| N9 | 上线冒烟 + Search Console | 用户拍板发布 | **0** |

**每站新做的只有**：配置 1 份、chrome 一套、模版每族 1 份、内容每页 1 份。**全部复用的是**：引擎三件套、装配契约、SEO 派生器、质量门、发布线、编辑器、翻译同步、管理软件——即整个系统的全部机器。这正是"dgcrane 是第一个例子/试验站"的准确含义：**dgcrane 验证的是机器，机器成了，后面每个站只剩内容工作。**

## 6. 多语言 × 多站的正交性

语言和站点是两个独立维度，互不纠缠：

- 站点隔离靠目录/前缀：`sites/<site>/`、`s3://sf-web/<site>/`；
- 语言隔离靠镜像树：`content/zh-CN/` ↔ `content/en/`，模版跨语言共享（marker 不含语言）；
- 所以「新站 × 新语言」不产生新机制——N 步剧本跑一遍 + 12 章同步流程即覆盖。

## 7. 引擎版本策略（多站后引擎怎么升级）

- 引擎升级只有两种：**bug 修复**（全站立即受益，geom 全站复验）与**契约演进**（16 章 G 节，minor 加 marker 向后兼容 / major 带迁移脚本）。
- 多站共用一份引擎意味着：**升级一次、全站复验一次**——`check` 聚合命令天然支持（登记派生，跑全部站点全部页面）。
- 禁止分叉：任何站不许持有私改版引擎。某站的特殊需求 → 契约提案，不是私改。
