# 14 · 门禁与验收体系（做到哪一步，才能进下一步）

> 各级验收判据原本散在 01/05/06/07/09/10 各章——判据在，但"门与门的先后关系"没有总表。本章把全部门禁合成一张梯子：**每一级说清三件事：完成判据（exit）、下一步入口条件（entry）、谁验收**。细节仍在原章（本章只做地图，不做第二真相源）。

---

## 0. 门禁三原则（先于一切门）

1. **判据必须可验证**：命令跑绿、清单打勾、演练有记录——"感觉可以了"不是判据。
2. **门禁失败不许绕**：唯一绕行 `git push --no-verify` 是显式留痕动作，事后必须补账（修掉或挂账）。
3. **提前必须显式**：确需跨门提前执行的项（如 P0 git 远端本属 M1①，因单点风险提前到现在）必须在 DECISIONS 标注理由——**允许提前，不允许默默提前**。

## 1. 门禁梯子（从小到大，六级）

### G0 · 改动门（每一次改动）
- **范围**：动了渲染器 / 模版 / MD / fragments 任意一处。
- **完成判据**：`npm run check` 绿 = validateBlocks + build + geom（**双视口**）+ 单测全过（06 章）。
- **过门才能**：提交/推送（pre-push 钩子拦截，06 章 §2）。
- **验收者**：机器。失败 = 改动停在工作区，不进真相层。

### G1 · 页面门（每个新页 / 每次结构改动）
- **完成判据**：对应 SOP 步骤走完（05 章）+ G0 绿 + geom 基准通过（还原页 vs 原站快照；新页 vs 族内参照，06 章）+ **入口核对**（导航/相关产品，SOP-1 第 8 步）+ 人工预览点头。
- **过门才能**：进入待发布集（产品期 = 状态"待发布"）。
- **验收者**：机器保结构与版式，**人保内容**（AI 只出草稿的红线落点）。

### G2 · 发布门（每次上线）
- **完成判据**：07 章 §4 检查单 7 条全过（check 绿、工作区干净对应 commit、sitemap/robots 已生成、`/zh/` 内链抽查、线上冒烟、release tag、安全响应头）。
- **过门才能**：本次发布记为 release；失败 = 线上保持旧版原样（原子性，02 章原理 6）。
- **验收者**：发布者（人点发布）+ 机器执行检查单。

### G3 · 批次门（搬迁 B0→B4，09 章）
- **入口条件**：上一批的门已过 + 本批前置就位（B1 需图片闸门+SEO+钩子；B3 需 B1 完成 + category 模版过 §9 七步验收；B4 需 B1–B3）。
- **完成判据**：该批 URL 映射表行**全绿**（迁入/301/显式放弃三态之一）+ 本批抽样 20% 人工对照通过。
- **纪律**：批内可并行，**跨批不许抢跑**。

### G4 · 里程碑门（M0→M3，10 章 §5）
- **入口条件**：上一里程碑完成线已过（显式提前项除外，见原则 3）+ 本里程碑所需拍板已决（DECISIONS 待拍板清单：M0 卡 #1–#3，M2 卡 #5，M3 卡 #4）。
- **完成判据**：
  - **M0**：01 章 v1.0 清单 **8 条全绿**（含第 8 条：13 章六透镜审计跑过且处置完整）。
  - **M1**：本机丢失零损失（裸远端 clone→build→deploy 演练通过）+ 运营在自己电脑完成一次"改值→发布"。
  - **M2**：运营不叫开发者独立完成"贴文章→预览→点改→发布"≥3 个真实页面 + 失败任务零污染验证。
  - **M3**：完成线随 DECISIONS #4 拍板后定义，未拍板不开工。
- **过门后**：上一级组件**冻结，只修不加**（10 章 §6）。
- **验收者**：用户（你）——里程碑是唯一必须你亲自验收的门。

### G5 · 冻结/扩建门（运营态）
- **入口条件**：冻结后任何新功能 = 触发表命中证据（01 章 §6）或已挂进某里程碑清单；例外通道仅 bug/安全修复（01 章 §5.4）。
- **完成判据**：扩建项本身按 G0–G2 走，并在 DECISIONS 留痕。
