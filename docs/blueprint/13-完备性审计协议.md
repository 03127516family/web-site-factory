# 13 · 完备性审计协议

> **存在理由**（2026-07-03，DECISIONS ⑧）：此前的完备性靠"用户每提一个角度、AI 补一轮补丁"——这是靠运气不是靠工程。本协议把"查缺"变成**可重复执行的程序**：六个透镜、固定触发时机、强制记录格式。跑完协议不等于零遗漏（没有审计能保证这个），但能保证**系统性的遗漏难以存活**；剩下的零星遗漏由执行期机制承接（06 章坑账、12 章矩阵纪律、golden set）。

---

## 1. 六透镜（每个透镜 = 一份强制过一遍的问题清单）

### L1 生命周期透镜
沿"构想 → 建设 → 上线 → 运营 → 演进 → 退役/迁移"走一遍，每个阶段问：进入条件、产出、完成线、回退路径是否都有归宿？
（当前落点：里程碑 M0–M3 = 10 章；运营态 = 12 章；退役/迁移 = 09 章 URL 映射与 301——**任何页面死掉都要有 301 归宿，站点本身将来退役同理**。）

### L2 角色透镜
逐个角色问"它需要什么、它会干什么坏事"：
**访客**（性能/移动端/可访问性）、**搜索引擎爬虫**（SEO/hreflang/robots）、**运营**（编辑/上传/历史回退）、**发布者**（审核/发布/回滚）、**管理员**（账号/站点配置）、**开发者+agent**（模版/引擎/知识包）、**垃圾源与攻击者**（表单反垃圾/后台认证/密钥）、**审计者**（一切变更可归因）。

### L3 数据透镜
逐类数据过 CRUD+B/R/M（建/读/改/删/**备份/恢复/迁移**）：
页面 MD、`site.md`、模版、fragments、图片（出货图+**原件**）、附件 PDF、**表单提交数据**（归宿/保留/导出）、统计数据、任务日志、账号、release 记录、翻译状态。
任何一类数据答不出"丢了怎么办、删时怎么办"即为缺口。

### L4 失效透镜（FMEA）
逐个组件问"它挂了会怎样、谁知道、怎么恢复"：
CDN/托管、托管 git、后台应用、生成 worker、构建 worker、LLM 通道、表单端点、统计脚本、本机（已答：M1 完成线 = 本机丢失零损失）。
铁律校验：任何组件失效都**不得影响访客读静态站**。

### L5 领域透镜（外贸 B2B 站要素）
产品/分类/文章/首页/联系、询盘（表单+反垃圾+数据归宿）、多语言、SEO、视频、PDF 下载、WhatsApp/社媒、地图、统计、备案、Cookie 合规（欧盟访客）、证书资质内容页。
（此清单随行业认知增补——它是活的。）

### L6 对标透镜
对照成熟系统（WordPress、主流静态 CMS、建站 SaaS）的功能清单问："它有而我们没有的，是**判定不做**（留档）还是**没想到**（缺口）？"
两个答案都合法，**没答案不合法**。

## 2. 触发时机（写死，不靠自觉）

| 时机 | 跑什么 |
|---|---|
| 每个里程碑完成线**之前**（M0/M1/M2/M3） | **全套六透镜**（已入 01 章 v1.0 清单第 8 条） |
| 新页族 / 新组件 / 新语言 / 新站点上线前 | 相关透镜（至少 L2/L3/L4） |
| 运营态每季 | 抽一个透镜轮换扫 |
| 重大外部变化（换托管、换模型、法规变化） | L4 + 相关透镜 |

## 3. 记录格式（强制）

每次审计在 [DECISIONS.md](DECISIONS.md) 留一条，逐项写：**发现 → 处置 → 位置**。
处置只有三种合法值：
1. **立即修**（补进对应章节/代码）；
2. **挂账**（进触发表/债务台账，带触发条件）；
3. **显式不做**（写明理由留档）。
"知道了但没记" = 违规。审计条目无未处置项，审计才算完成。

## 4. 协议的诚实边界

- 设计期审计只能穷尽"可预想的"；**执行是最后的审计员**——所以坑账（06 章 §4）、传播矩阵"表外无改动"纪律（12 章 §1）、生成 golden set（11 章 §2.4）都是执行期的接盘机制，三者与本协议构成闭环。
- 透镜清单本身允许生长：执行中发现第七个透镜（例如"成本透镜"），先补本章、再跑它——与矩阵纪律同构。
