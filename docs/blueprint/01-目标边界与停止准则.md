> 本章回答四个问题：要什么（精确到可验收）、不要什么（负面清单）、做到什么算完（v1.0 判据）、**做到什么时候停止**（冻结线与触发式扩建）。
>
> **2026-07-03 更新（适用范围）**：本章写于产品化拍定之前，适用范围 = **内核 + dgcrane 首站（即路线图 M0）**。产品化主线见 [10 章](10-产品化形态与路线.md)：触发表中「托管编辑器」「建页薄壳」两项已从触发式**转为 M1 / M2 主线**，非目标表中「托管后台」一行同此升级；其余条款（v1.0 判据、停止线、反停止、其它触发项）继续有效，且逐里程碑套用——每个 M 有自己的完成线（10 章 §5/§6）。

## 1. 背景：真正要替换的是什么

现网站基于 WordPress。要替换的不是"WordPress 这个软件"，而是它代表的**生产方式**。四条真实痛点：

1. **攻击面与运维税**：WP + 插件的 CVE 流水线、PHP 活服务器、MySQL——一个产品目录站不需要"每次访问都现拼页面"，却要为此常年养服务器、打补丁。
2. **性能天花板**：动态渲染 + 插件堆叠，怎么优化也追不上"静态文件 CDN 直出"。
3. **内容生产方式过时**：给内容的人（业务方）不产结构，产结构的人（主题开发者/建站公司）贵、慢、还会离场。页面构建器产出的是焊死的快照，改一处要人肉找遍全站。
4. **证据就在仓库里**：现库两个死表单（WPForms `713`/`780` 静态快照，`<form>` 无 action，订阅表单 action 里还嵌着抓取时的 Google 追踪参数）就是老生产方式的遗物——**页面死了都没人知道**。

## 2. 目标与两条硬需求的精确化

### 2.1 目标一句话

> 建立"内容驱动页面表达"的静态站生产系统：业务方给**内容**（文章/资料/图），AI 负责**判断与创作**（归类成结构化 MD、必要时造模版），代码负责**确定性装配**（MD→HTML→发布），人负责**验收与拍板**。产出一个无服务器、无数据库、单人可运维的静态站，替代 dgcrane 现有 WordPress 站。

### 2.2 硬需求 A：「借助 AI 实现 ~80% 静态化」

这句话两重含义，**都成立，都验收**：

**含义①（交付形态）：站点 100% 静态，动态触点白名单化。**

| 触点 | 形态 | 状态 |
|---|---|---|
| 询盘表单提交 | 静态表单 + 一个外部提交端点（第三方或自建，待拍板） | 待定（07 章决策包） |
| 站内搜索（可选） | 构建期生成静态索引（如 pagefind），仍无服务器 | 触发后再建（09 章） |
| 客服 / AI Bot（可选） | 第三方 `<script>` 嵌入 | 触发后再建 |

**白名单之外不得出现任何动态依赖。** 页面主体、相关产品、导航、面包屑、图库，全部构建期定死。超出白名单的"动态需求"一律进 §6 触发表走流程，不许顺手实现。

**含义②（工时分配）：AI 承担 ~80% 生产工时。**

| 阶段 | 人（~20%） | AI agent（~80%） | 代码（0%，免费） |
|---|---|---|---|
| 建站期 | 给料（文章、图、产品名、slug）；拍板（托管、表单、上线）；验收预览 | 烧 MD、造模版（新页族）、登记接线、跑验证并修到 1:1、SEO 落地、批量搬迁执行 | build / render / verify / deploy 全确定性 |
| 运营期 | 编辑器里改字换图；点发布 | 只在新增页面/页族时出场 | 重渲 + 部署 |

判据：新增一个标准产品页，人的动作 ≤ 3 个（给文章、给名字和 slug、看预览点头）——这已经是现行 §3 工作流协议，蓝图将其固化为验收项。

### 2.3 硬需求 B：「可见即可编辑」→ 三级编辑模型

"可见即可编辑"不是"页面上任何东西都能改"——那与"版式不烂"物理互斥（推导见 [02 章](02-第一性原理.md)原理 4）。精确承诺如下：

| 级 | 改什么 | 谁 / 工具 | 生效路径 | 承诺等级 |
|---|---|---|---|---|
| **L1 值** | 文字、富文本（段落/加粗/列表/表格）、图片、链接、重复项增删 | 运营 / `npm run edit`（:8081）就地点改 | 定点写回 MD → build 重渲 | **产品级承诺：可见即可编辑，全覆盖** |
| **L2 结构** | 段落有无、顺序、字段增减 | 懂 MD 的人或 agent，文本编辑 `src/content/*.md` | 改 MD（模版 `data-optional` 已备好裁剪）→ build | 半自助：改文本即可，`validateBlocks` 兜底报错 |
| **L3 版式** | 布局、样式、新的段落类型 | agent 改模版 | 改 `src/templates/` → `verify:geom` 验证 | **明确不承诺就地编辑**；改版 = 重烧骨架 + 验证 |

原理：L1 高频低险 → 给界面；L3 低频高险 → 给验证；L2 居中 → 给文本。频率与风险决定工具，不是反过来。

### 2.4 隐含需求（对话中反复出现，就此固化）

- **1:1 保真**：凡"还原老站页面"，逐元素几何 1:1（`verify:geom`），不接受"差不多"。
- **单人可运维**：无服务器、无数据库、无账号体系可养；一台电脑 + 一个 git 仓库 + 一个静态托管就是全部。
- **上下文可丢弃**：换一个 AI 会话、换一台机器、换一个人，凭仓库（MD + 模版 + 蓝图 + CLAUDE.md）即可无损继续。这是"**上下文是耗材，MD 是资产**"的工程含义，也是为什么所有约定必须落文档、不许留在对话里。

## 3. 非目标（负面清单）

以下明确**不建**。每条给理由与"何时翻案"的指针：

| 不建 | 理由 | 翻案条件 |
|---|---|---|
| PostgreSQL / 任何数据库 | git 就是版本库+审计日志；单人单站建 DB 是重新发明 git 且更差 | 触发表：多人并发编辑 |
| 账号 / 权限 / 审批流 | 现在只有一个人 | 触发表：第二个编辑者 |
| 在线模版编辑器 | 模版是 L3 版式层，改它必须过 verify:geom，界面化有害 | 不翻案 |
| 托管后台（把编辑器挂公网） | 本地够用；挂公网要加认证与防护，是纯成本 | 触发表：非技术运营需要远程改值 |
| 多语言（现在） | /zh/ 前缀已预留位置，其余都不做 | 用户拍板做英文站（09 章有预留方案） |
| 多站点管理 | 首期一站 | 真出现第二个站 |
| A/B 测试、个性化、推荐 | 目录站无此需求 | 不翻案（真要做也是站外工具的事） |
| 无审核自动发布 | AI 永远只出草稿，人是发布闸门 | 不翻案（红线） |
| SEO 内容策略/外链/关键词调研 | 不是代码能解决的（2026-07-01 决策：SEO②层不做、不拍脑袋硬做） | 不翻案（归运营） |

## 4. v1.0 上线验收清单（= 建设停止线判据）

全部勾选即 v1.0 完成。每条带验证方式，不接受"应该可以"：

- [ ] **1. 搬迁完成**：老站目标页面 100% 有归宿（迁入新站或进 301 映射表）；按 [09 章](09-搬迁计划与未来扩展.md)抽样验收通过。
  验证：URL 映射表逐行核对 + 抽样 20% 人工对照。
- [ ] **2. 发布线可用**：部署一条命令、回滚一条命令，**回滚至少实弹演练过 1 次**。
  验证：演练记录（deploy 新版 → rollback → 线上回到旧版 → 再 deploy）。
- [ ] **3. SEO hygiene 全绿**：canonical / OG / JSON-LD / sitemap.xml / robots.txt / 面包屑 JSON-LD 化 / 图片过闸门，逐项见 [08 章](08-SEO与性能.md)清单。
  验证：08 章验收清单 + Google Rich Results Test 抽测。
- [ ] **4. 询盘能收到**：表单方案落定（第三方或自建）且真实提交一次能到达指定邮箱/后台。
  验证：实弹提交测试。
- [ ] **5. 质量门自动化**：`npm run check`（测试+build+geom）挂进 pre-push 钩子或 CI，绕过需显式 `--no-verify`。
  验证：故意提交一个坏 MD，推送被拦。
- [ ] **6. 遗留清零或显式挂账**：CLAUDE.md §8 每条要么关闭、要么写明"转触发表/不修的理由"。
  验证：§8 逐条核对。
- [ ] **7. 站点杂项齐备**（2026-07-03 完整性审计补，DECISIONS ④/⑤/⑧）：404 页面；流量统计埋点（选定统计工具，进 chrome fragment；**外贸站有欧盟访客——统计选型时同步判定 Cookie 同意条需求，选无 Cookie 统计可免横幅**）；favicon/站点图标核对；**若国内托管：ICP 备案号页脚展示（法定要求，随 07 章托管拍板联动）**；隐私政策等法务页归入搬迁 B4；不做项判定留档（评论、RSS、定时发布——B2B 目录站不需要；真需要时评论走第三方嵌入、定时发布走 CI 计划任务）。
  验证：逐项打开确认 + 判定记录在案。
- [ ] **8. 完备性审计全套跑过**：按 [13 章审计协议](13-完备性审计协议.md)六透镜扫一遍，发现项全部处置（立即修/挂账/显式不做），DECISIONS 留痕、无未处置项。
  验证：审计记录存在且处置完整。
- [ ] **0.（前置，立刻做）仓库有异地远端**：git remote 建立且推送成功。**此条不等 v1.0，本周就该做。**

**明确不属于 v1.0 的**：排名提升、流量增长——那是 SEO②层（内容/外链/运营），2026-07-01 已拍板不在本系统范围。v1.0 的定义是：**老站可以下线，新站可以运营**。

## 5. 停止准则（做到什么时候停止）

### 5.1 建设冻结线

§4 清单全绿 → **系统开发冻结**。引擎、编辑器、脚本不再加任何功能。

### 5.2 运营态定义

冻结后只剩三种动作，全部不写代码：

1. **新增内容**：给料 → agent 烧 MD → build → 验收 →发布（[05 章](05-工作流程SOP.md) SOP-1/2）。
2. **修改内容**：`npm run edit` 点改（SOP-4）。
3. **发布**：`npm run deploy`（SOP-8，发布线建成后）。

### 5.3 反停止条款

- 冻结后想加任何功能，必须出示 §6 触发表的**命中证据**（可观测的信号，不是"感觉会用到"）。
- "顺手做了"= 违规。此条是对 2026-06-25 再平衡决策（"刹住往深做工具、优先把产品搬进来"）的制度化。
- 判断口诀：**做内容永远合法，做工具必须过触发表。**

### 5.4 例外通道

Bug 修复、安全修复、依赖安全升级不受冻结约束——修复不是功能。

## 6. 触发式扩建表

| 信号（必须可观测） | 才建什么 | 量级 | 预留设计 |
|---|---|---|---|
| 出现第二个编辑者，且发生 ≥1 次改动冲突 | 编辑器托管 + 登录 + 简单锁 | 数天 | 09 章 §4 |
| 非技术运营需要**独立**建页（月建页 >8 且"等 agent"成为瓶颈） | Agent SDK 薄壳："贴文章 → 出预览链接" | 1–2 周 | 09 章 §4 |
| 用户拍板做英文站 | 多语言流程（MD 镜像树 + git 增量翻译） | 按页量 | 09 章 §2 |
| 内容页 >150，或用户/访客反馈"找不到内容" | pagefind 构建期静态搜索 | 1–2 天 | 09 章 §3 |
| 出现真实产品数据库（库存/价格/参数中心化管理） | 动态 API 层 | 另立项 | 07 章 §5 |
| 页面数 >100 且全量构建/geom 明显变慢 | 增量构建 + 按需 geom（只重验受影响页族） | 数天 | 06 章 §2 |
| 需要频繁全站换皮/改结构 | **无需扩建**——改模版全族重渲即可，这正是当初选渲染器路线的红利 | — | — |
| 出现第二个网站 | 多站点复用引擎 | 另立项 | — |

## 7. 运营态维护节拍（冻结后的最小维护）

| 周期 | 动作 |
