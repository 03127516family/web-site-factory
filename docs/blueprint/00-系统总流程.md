# 00 · 系统总流程（主轴·详细设计版）——从一份 MD 到多语言托管站的完整链路

> **这份是主轴**，01–17 章是它每一段的放大。v2（2026-07-03）：应用户要求"对每一步进行详细的设计"，每段展开为【输入→输出 / 谁干 / 详细流程 / 失败与回退 / 验收门】五件套。两份新支柱：**[16 装配契约](16-装配契约.md)**（AI 组的 HTML 必须守的规则=引擎能接管的原因）、**[17 引擎与站点分离](17-引擎与站点分离.md)**（下一个站怎么零改引擎复用）。

## 系统身份（一句话钉死）

> **用 AI 操作、以 Markdown 为真相、代码与 AI 都能把 MD 组装成 HTML、产出静态站、发到 S3/CloudFront、少量动态走 Lambda、支持多站点多语言、运营在浏览器里可见即可编辑——用来取代 WordPress。**

五条不可动摇的属性：① 取代 WordPress（无 PHP、无 MySQL、无活服务器渲染）；② **抛弃 Python**（全栈 Node+云）；③ 静态优先，动态少而白名单化；④ AI 是操作者（创作、翻译、装配都可由 agent 干）；⑤ 多站点 × 多语言从数据模型第一天就不阻断（[17 章](17-引擎与站点分离.md)：dgcrane 只是第一个试验站，机器全部复用）。

## ① 原料 → MD 真相（烧制）

**输入→输出**：裸文章/旧 WordPress 页/产品资料（`content/<lang>/raw/`）＋产品名＋slug → `content/<lang>/<slug>.md`（git 提交）。
**谁干**：AI agent（本地=Claude Code 会话；云端=`generate` Lambda）。这步需要**语义判断**（哪段是概述/规格/FAQ），是 AI 的活，不是脚本。

**详细流程**：
1. **判族**：这页是 product / post / category / …？→ 决定用哪份模版（族已有模版→直接用；新族→先走 ② B 路造模版）。
2. **切块判形**：正文从上到下切段，每段归入四形态之一（单值/长正文/重复/可选，§9 速查表）。
3. **映射槽位**：每块对到模版的槽，三看——语义对得上、载体合法（多段富文本必须对 `<div data-field>` 槽，契约 D1）、顺序与原文一致。
4. **写 frontmatter**：`page:` 登记块（slug/type/lang/title/description/template，契约 A1）+ 数据字段 + 重复区数组。**登记即内容，无第二登记处**（F1）。
5. **写正文块**：`## 标题 <!--block:KEY-->`，KEY 与模版槽对齐（契约 A3）。
6. **L2 SEO 顺手做**（08 章四层模型）：标题措辞、description、图片 alt、按关键词表布内链。
7. **自检**：`validateBlocks` 过（C1）→ 本地 build 出页 → 有基准则 geom。

**失败与回退**：validateBlocks 抛错→修 MD（永不改引擎）；素材缺失→known-leftover 占位（契约 D5）+ 记台账。
**验收门**：C1 过 + build 成功 +（有基准时）geom 1:1 → 才准 commit（14 章 G1）。

## ② MD → HTML（两条组装路，产物同构可互换）

**输入→输出**：MD + 模版/骨架 + fragments → **带 marker 的 HTML**（编辑/验证用）与**剥 marker 的干净 HTML**（出货用）。
**用户硬要求**：AI 能组装，代码也能组装。两路并存的前提是**产物同构**——这由 [16 装配契约](16-装配契约.md) 保证，后面 ③④⑤⑥⑦ 一概不关心页面是谁组的。

**A 引擎路（默认，覆盖 ~95%+ 场景）**——`composePage` 的确定性装配线：
1. `loadPages()` 扫 content 目录派生登记表（无手写数组）；
2. 读该页模版 → `render.mjs` 按 marker 填 MD 值（克隆重复区/裁可选段/富文本转换）；
3. 注入 fragments（header/footer/询盘表单，`{{INQUIRY_FORM}}` 等占位符）；
4. 注入 `{{SEO}}`（见 ③）；
5. 生产态剥全部 `data-*`；编辑态保留并生成 `data-md` 写回坐标。
每次 build 免费、可复现、批量。

**B AI 路（结构创作）**——AI 什么时候上、产出什么（决策树）：

| 场景 | AI 做什么 | 之后 |
|---|---|---|
| 新页族第一次 | 按 §9 七步法造**自声明超集模版**（一次） | 全族回 A 路，引擎零改动 |
| 一次性特殊版式（如某篇图文混排文章） | 造**每页一份骨架模版**（posts 族模式：布局=死骨架带 marker，值=MD） | 该页仍走 A 路填值，改字自动重渲 |
| 骨架都表达不了的页面 | 直写 dist 成品 HTML（**逃生舱，须用户特批**） | 仍守装配十律；守了迟早收敛回 A 路（multi-point 页逐字节实证） |

**两路铁律**（契约 E 节装配十律的浓缩）：无论谁组，产物带同一套 marker、值全部来自 MD、引擎按同一 MD 能重渲出同构 DOM（同形律）。**所以 AI 组的页照样能被引擎重渲、被编辑器编辑**——这是两路能共存的全部原因，也是你问的"AI 生成的 HTML 必须符合的规则"的所在（详见 16 章 E/F 节，含机器判定 C1–C4）。

**失败与回退**：C1–C4 任一不过→页面不合规、不准发布（publish Lambda 里跑同一套检查）。
**验收门**：A 路=check 全绿；B 路产物额外过 C3 同形比对。

## ③ SEO（从 MD 自动派生，L1 已实现）

**输入→输出**：该页 MD 的 `page:` 块 + 首图 → `{{SEO}}` 填充的 head 标签组 + 全站 `sitemap.xml`。
**派生表**（全部同源自 MD，零手写）：

| 产出 | 来源 |
|---|---|
| canonical / og:url | `site.config.baseUrl` + slug（17 章 P-1 搬家后） |
| title / og:title / description | `page.title` / `page.description` |
| og:image | 该页 MD 首图字段 |
| JSON-LD | type=product→`Product`、post→`Article`；都带两级 `BreadcrumbList` |
| sitemap.xml | 遍历登记生成（同源不漏页），lastmod=该 MD 的 git 提交日期 |

**责任四层**（08 章）：L1 技术标签=构建期代码自动；L2 页面语义=①烧制时 AI 顺手；L3 关键词→页面映射=AI 调研起草；L4 外链=不做。
**多语言 SEO**：每语言独立 canonical/sitemap；hreflang 成对 + x-default，与语言切换器同源派生（12 章 §3.7）。
**验收门**：单测 7 项（canonical 唯一/JSON-LD 可解析/sitemap 不漏页/转义）已在 check。

## ④ 多语言（数据模型）＋ 发布（S3 存储与原子发布）

**多语言数据模型**（同步动作在 ⑦）：
- `content/zh-CN/<slug>.md` ↔ `content/en/<slug>.md` **路径镜像即配对**，不建配对表；
- 模版跨语言共享（marker 不含语言）；每语言独立 `page:` 登记，输出 `/zh` `/en`；
- 目标语言 MD 带 `i18n.source_commit`（译自源语言哪个 commit）——⑦ 增量同步的锚点；
- 目标语言 MD 也是真相、也可被 ⑥ 编辑。

**存储：三个 S3 平面 + git，各存各的**：

```
git（源真相：版本/diff/作者/审计，全是 git 原生能力，不建数据库当真相）
  sites/<site>/content/<lang>/*.md · templates/ · fragments/ · site.config
  engine/（跨站共享，契约版本化）

s3://sf-drafts/<site>/<lang>/<slug>.md          草稿平面（⑥ 实时保存落这，未发布）
s3://sf-web/<site>/<lang>/…/index.html          发布平面（CloudFront 源，访客拿的）
s3://sf-web/<site>/assets/{css,js,img,files}
s3://sf-media/<site>/…                          媒体（运营上传，压缩后）
```

**为什么发布产物不进 git**：git 存"菜谱"（MD/模版），S3 存"做好的菜"（HTML）。菜丢了照菜谱一键重做，所以菜不必进 git。

**发布动作 = `publish` Lambda（原子，8 步）**：
1. 冻结输入（该页/全站 MD 的 commit SHA）；
2. 引擎渲染（与本地同一 `render.mjs`）；
3. 合规检查（C1–C4，同质量门）；
4. 写 `sf-web` 临时前缀；
5. 校验（页数对齐、内链探活、sitemap 一致）；
6. 原子切正式路径；
7. CloudFront 失效刷新；
8. 打 git release tag（发布历史=tag 列表）。
**任一步失败→线上保持旧版**；**回滚 = `rollback` Lambda 重发上一 tag**（重算，不是改指针，保证可重现）。

**验收门**：14 章 G2 发布门——check 全绿 + 发布授权档（现按最严：一切发布等用户点头）。

## ⑤ 访问（访客侧：纯静态 + 白名单动态）

- 访客 → CloudFront → `sf-web` 静态 HTML。**无服务器渲染、无 PHP、无数据库**——取代 WordPress 的核心红利：攻击面≈0、快、便宜、后台全挂也不影响访问。
- 共存路由：CloudFront 多源——`/zh/*`→S3，其余→老站，逐步切流量，无需一夜割接。
- **动态白名单（≤3 个，全外置）**：询盘表单 POST→`form-submit` Lambda→Postmark（现 mock，端点单常量切真改一行）；可选站内搜索=构建期静态索引（pagefind，仍无服务器）；可选客服脚本。**动态挂了不影响静态主体**。
- **失败模式**：S3 单区故障→CloudFront 缓存兜底；Lambda 挂→表单降级提示邮箱直达；证书/DNS 由基础设施告警。

## ⑥ 他人修改（云端可见即可编辑——端到端往返）

**输入→输出**：运营在浏览器里点改 → MD 定点更新（草稿）→ 预览 → 发布。
**三级编辑模型**（可编辑性与自由度互斥的物理边界，02 章原理 4）：L1 值（点改，全覆盖）；L2 结构（增删段/行，改 MD）；L3 版式（改模版+geom 复验，不在后台做）。

**详细往返（L1 值编辑）**：
1. 管理软件页面列表 → 点「编辑」→ 若该页有他人编辑锁（DynamoDB，TTL 自释放）→ 提示接管或只读；
2. iframe 载入该页**带 marker 版**（`render-page` Lambda 编辑态渲染）+ `editor.js`；
3. 点某处 → editor.js 读 `data-md`/`data-group`/`data-idx` 算出 MD 坐标（`fm:` / `mdhead:` / `mdbody:`）+ 新值（富文本经 `htmlToMd` 反转）；
4. POST `{site, lang, slug, 坐标, 类型, 值, 基准版本}` → API Gateway；
5. `edit-save` Lambda：取当前草稿（无则取 git HEAD）→ **`patchMarkdown` 定点改写**（现成纯函数）→ 写 `sf-drafts`；
6. **冲突检查**：请求带的基准版本 ≠ 当前草稿版本 → 拒绝并返回最新（后写不覆盖先写）；
7. 重渲该页 → 返回预览 URL → 运营所见即所改；
8. 满意 →「发布」→ ④ 的 publish（草稿 MD 先 commit 回 git，真相闭环）。

**增删重复项**：editor.js 现有的增删 UI（`data-repeat` 区）同坐标协议走 5–8。
**关键复用**：`editor.js` / `patchMarkdown` / `render.mjs` 是**现有本地纯函数，被 Lambda 原样当载荷**，一行不重写——本地内核就是云端引擎本体。
**失败与回退**：草稿永远不污染 git（发布时才 commit）；丢弃草稿=删 drafts 对象；断网→前端重试队列。
**验收门**：round-trip 单测（C2）+ 编辑后该页 geom 不变（值编辑不该动版面）。

## ⑦ 同步修改到其他语言（改了中文，英文怎么办）

**输入→输出**：源语言某页发布 → 目标语言"过期字段清单"→ 只重译变更字段的目标语言草稿 → 人审 → 各语言独立发布。

**详细算法（字段级增量；主线=编辑事件驱动版本戳，git 仅兜底，2026-07-03 ⑳ 用户拍板）**：
1. **信号在编辑时就产生**：改中文某段，编辑器天然知道坐标（如 `overview`），保存时给源 MD 该字段的版本戳 +1（`i18n_rev.overview`）——不需要事后算、不取历史；
2. **过期 = 数字比对**：目标语言 MD 记着每字段译自的版本戳（`translated_rev.overview`）；目标戳 < 源戳 = 该字段过期。两个当前 MD 里的数字一比即知；
3. 目标语言页标状态：**最新 / 已过期 n 处 / 冲突待人工**，显示在 ⑧ 的 i18n 面板；
4. `translate` Lambda：AI **只重译过期字段**（其余一字不碰）→ 写目标语言草稿 + 把该字段 `translated_rev` 抬到源戳（回到已同步）；
5. 人审（双语对照视图）→ 目标语言独立走 ④ 发布 → 该语言该文章 HTML 重渲，其余不动；
6. **兜底**：若源被绕过编辑器改动（手改文件 / AI 整篇重烧，无编辑事件、没 +戳），退化为整篇待复核，可选用 git 取上次同步版做一次字段级 diff 补清单——**非主线，日常走编辑器用不到 git**。

**保护规则（机制保证，非约定）**：
- 英文侧人工润色过、而中文源没再编辑（源戳没涨）的字段 → **永不被机翻覆盖**（任务只碰"目标戳<源戳"的字段）；
- 中文该字段过期 & 目标也被人改过 → 标"冲突待人工"，不自动动；
- 换版式（改模版）全语言零翻译成本（模版共享，内容没变）。
详见 12 章。

## ⑧ 管理（管理软件详细设计）

**形态**：静态 SPA（admin 子域 + CloudFront）+ API Gateway + Lambda + DynamoDB。**后台不在访客链路上**——后台全挂，线上站照常访问。

**界面清单**：站点切换器（从 `sites/` 目录派生，17 章 N8）/ 页面列表（状态、语言、i18n 过期标记）/ 可视编辑器（⑥）/ 新建页（贴原料→`generate`）/ 发布与回滚（历史=tag 列表）/ 媒体库（上传→`media-ingest` 压缩落 `sf-media`）/ i18n 面板（⑦ 状态与一键重译）/ 任务日志。

**角色**（Cognito）：编辑者（改草稿）/ 发布者（点发布）/ 管理员（用户与站点）。**AI 永远只出草稿，发布必经人**。

| 组件 | 选型 | 存什么/干什么 |
|---|---|---|
| 前端 | React SPA（静态托管） | 上述界面 |
| API | API Gateway + Lambda | 下方清单 |
| 元数据 | DynamoDB | **非真相**：任务状态/页面锁(TTL)/发布历史缓存/用户偏好。页面列表**从 content 目录派生**（F1 思想，真相仍 git） |

**页面状态机 = git 的投影**（不另建状态库）：草稿（sf-drafts 有对象）→ 预览就绪 → 待发布 → 已发布（git tag）。审计 = commit 历史 + 任务日志。

## 现有本地内核 = 云端引擎本体（不重写，只打包）

| 本地纯函数 | 云端角色 |
|---|---|
| `render.mjs` | `render-page`/`publish`/`rollback` 的载荷 |
| `patchMarkdown`(md-write) | `edit-save` 的载荷 |
| `editor.js` | 直接跑在浏览器 iframe 里（本就前端） |
| `validateBlocks`/`verify-geom` | CI 质量门 + publish 前合规检查（C1–C4） |
| `build.mjs::loadPages` | 页面列表 API 的实现 |

**这就是坚持"引擎是纯函数、零名字逻辑"的全部回报**：本地怎么跑，云端就怎么跑。而它们能服务下一个站，靠的是 [16 契约](16-装配契约.md)（引擎只认 marker）+ [17 分离](17-引擎与站点分离.md)（站点常量全部外置，纯化清单 5 项在案）。

## 抛弃 Python（落实）
