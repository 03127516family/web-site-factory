# 自声明模版 + 引擎零写死 —— 设计草案

> **状态：设计草案，未实现。** 落地时机 = 做第二个页族（文章/分类…）时（那时收益从「洁癖」变「刚需」）。
> 现阶段只守规矩（不往引擎新增按名字的逻辑），不重构。
> 关联：`CLAUDE.md` §2 引擎铁律、`src/templates/product.contract.md`。

## 0. 目标

**一个 `render` + 一个 `edit`，通用、永不写死，任何页族（产品/文章/分类…）都能用。**
做法：把引擎现在「靠名字查表」的每件事，改成「模版用属性自报」，引擎只读属性、不读名字。

三层分离（引擎永远 1 个、不动；变多的只是「模版」这种 HTML 声明）：
- 引擎 `scripts/render.mjs` + `public/assets/js/editor.js` —— 纯逻辑，不认任何具体名字。
- 模版 `src/templates/*.html` —— 用 markers 自报结构，每页族 1 个。
- 内容 `src/content/*.md` —— 每页 1 个。

`editor.js` 已是此标准（只读 `data-md/edit/group/idx`）；本草案是让 `render.mjs` 也达到同样的「名字盲」。

## 1. 迁移地图：每张写死的表 → 搬成哪个属性

| 现在写死在 `render.mjs` | 搬成模版属性 | 约定兜底 |
|---|---|---|
| `REPEAT_FM_ARRAY[组]="md.路径"` | 容器 `data-array="md.路径"` | 不写则默认 = 组名 |
| `REPEATS[组].prefix`（给 `data-block-id` 用） | `data-prefix="x"` | 不写则 = 组名 |
| `NO_STRUCT_EDIT={gallery}` | 容器 `data-no-add` | — |
| `classifyField` 的 `hero.highlights`/`installation.body` 等名字特判 | 该点 `data-edit="rich"` 明示 | 不写则按内容形态猜 |
| `STRUCTURED_BLOCKS` 例外清单 | **取消**（见 §2 第 4 条） | — |

搬完，所有「名字」从代码挪进模版；模版自己声明「我这个重复区数据在 `md.路径`、不显增删按钮」。

## 2. render 的目标算法（纯标记驱动，零名字）

```
扫 [data-field]    → 按属性路径取 MD 值，按 data-edit(或内容形态) 填
扫 [data-repeat]   → 按 data-array 取数组，逐项克隆单元、填字段；editMode 且无 data-no-add 则挂增删
扫 [data-optional] → MD 无该 key → 删整段
扫 ## block:KEY    → d[KEY]={title, mdToHtml(正文)}，被 data-field="KEY.body" 自动接走
```

第 4 条让 `STRUCTURED_BLOCKS` 例外清单消失：某块是不是重复、要不要内嵌图，全由模版的 `data-repeat`/`data-field` 自声明，引擎不需要「哪些块特殊」的名单。

## 3. 难点：双处结构 → 趁机收成单处

`components`/`crane-types` 现在 name 在 frontmatter 数组、body 在 `## block` 的 `###`，靠 index 对齐 —— 最别扭的一处。
- **(a) 声明它**：容器标 `data-array="components_images" data-body-block="components"`，引擎按 index 并。能跑，但「按 index 对齐两个出处」本身脆。
- **(b) 收成单处（推荐）**：一个组件的名/图/正文只放一个地方（全进 frontmatter 数组项，或全进 `### 名` 段）。无双处、不对齐、不错位。

**自声明是干掉双处结构（缺口 §D.8 那个味道）的最佳时机，建议走 (b)。**

## 4. 诚实的边界：哪些搬不了、也不该搬

自声明搬走的是**名字**，不是**通用逻辑**。以下永远留在引擎，且应该留：
- `mdToHtml`（markdown→HTML、表格、内嵌图）—— 通用转换，不认名字。
- 内容形态启发（含 `<`→rich、含 `<table>`→套 `.custom_tables`）—— 通用，不认名字。
- 克隆 / 裁剪 / 填充的机械 —— 通用。

> **核心原则：自声明把「名字」搬出引擎，但不搬「通用逻辑」（也不该搬）。**
> 引擎可以一直长新能力（更多 markdown、更多内容启发），但**永远不长一个具体名字**。
> 守的从来不是「代码零行数」，是**「零按名字的分支」**。

## 5. 落地后：加一个全新页族的流程

```
用户:  "做个文章页族，这是第一篇:<文本>，slug:xxx"
AI:   ① 写 templates/article.html —— 用 data-field/repeat/array/edit 声明结构（一次性）
      ② 烧这篇 MD  ③ build + verify
之后该页族每篇:  用户只给文本+slug，引擎一行不动
```

引擎（render+edit）自始至终一个、没碰过；新增的只有 `article.html` 这张声明。

## 6. 守卫：`npm run check`（linter，同期落地）

自声明把结构交给模版后，加一个校验器：扫模版每个 `data-field`/`data-repeat`，核对 MD 有没有喂、`data-array` 路径在不在、`data-edit` 合不合法 —— **声明错就构建红**。把「规范靠自觉」升级成「规范靠机器」。同样等第二个页族时再上。
