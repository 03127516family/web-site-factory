# 多语言翻译块重设计（推翻 F3，生产级）

> 日期：2026-08-12。状态：设计定稿，待用户评审。
> 起因：F3（MD 时代 i18n 的 JSON 平移）是 POC 级——翻译节点=会话内 AI、CLI 驱动、字段级戳、整页暂扣门禁。用户拍板"要系统性、能上线的"，逐点讨论后推翻重来。
> 本文档是唯一设计依据：8 条决策全部经用户逐点拍定（讨论过程见当日对话记录）。

---

## 1. 拍定决策清单（D1-D8）

| # | 决策 | 内容 |
|---|---|---|
| D1 | 翻译主力 | **AI 出草稿 + 人审上线**（混合制）。AI 只产草稿，发布永远过人 |
| D2 | 触发 | 中文「**发布**」事件 → 自动结构同步 + 自动送翻。**缺段照发，整页永不下线**（业界对齐：WPML/Polylang/Weglot/TranslatePress 均无页面下线行为）。草稿永远跟最新源，不积压历史版 |
| D3 | 控制台 | 最小面板四件：**① 自动翻译开关 ② 待审亮灯 ③ 手动送翻 ④ 术语表管理**。完整后台缓建（维持 T4） |
| D4 | 引擎 | **DeepSeek** 首发；引擎层可换（callAI 依赖注入，同烧制台纪律） |
| D5 | 粒度 | **句级 + 翻译记忆库（TM）**。翻译单元 = 句子（标点切分），TM 复用已审译文 |
| D6 | 存量 | 8 页 zh / 2 页 en 的欠账，走同一条流水线批量补（控制台③同一按钮） |
| D7 | 术语表存储 | **JSON**（terms.\<src\>.\<tgt\>.json），YAML 退役。理由：R6 全系统 JSON 一致、schema 校验复用、数据库迁移直通（R13/T3 同路） |
| D8 | 术语表管理 | **用户（审稿人）自定义**：控制台表格增删改，校验落盘 |

## 2. 核心架构：TM 是真相，镜像是投影

```
中文源 JSON（真相，人写/AI烧）
     │  切句
     ▼
翻译记忆库 TM（真相：源句指纹 → {译文, 状态, 元数据}）
     │  投影（纯函数）
     ▼
镜像 JSON（物化：骨架 ≡ 源树，文字 = TM 投影）→ build → dist
```

- **TM（翻译记忆库）是翻译的唯一真相**：`{ "句指纹": { text, translation, status: draft|approved, origin, updatedAt } }`，按语言对一份文件（`site/src/i18n/tm.zh-CN.en.json`）。句指纹 = 源句内容 sha1 前 12 位，**位置无关**——重排、跨页移动免疫。
- **镜像 JSON 降级为物化投影**：镜像 = project(源树, TM)，可全量重建——与 registry.json 同哲学（索引/投影不是第二真相）。镜像保留落盘的原因：编辑器要服务它、预览要看它、geom 要比它。
- **审稿人直改镜像（R44 沿用）= 写回 TM 并置 approved**，再重投影镜像。两条入口（审清单里改 / 页面上直接改）同一个写回点。
- **取代**旧 F3 的 `i18n_rev` / `translated_rev` / `i18n_fp` 字段级三件套——句级 TM 天然携带新旧信息（指纹即版本），不再需要手工抬戳。

## 3. 句子切分规则（D5 的工程护栏）

翻译单元 = **句**。切分规则：

1. 中文句界：`。！？…`；英文句界：`. ! ?` 且后跟空格/大写/结尾。
2. **不切**：数字中的小数点（`3.5 吨`）；缩写白名单（`U.S.A.`、`Mr.` 等，初值实现期定）。
3. 无标点短文本（标题、按钮、表格单元格、图片 alt）= 整体一句。
4. **跨句行内标记不硬切**：链接/加粗横跨两句 → 合并为一个单元（保 marks 不烂）。
5. 结构化非文本节点（table 的行列结构、列表层级）不进单元——骨架代码持有，TM 只存文字句。
6. **结构性排除字段**（图片 src、链接 href、面包屑 trail 等 U-1 排除项）不进切句；图片 alt 进（§3.3）。

## 4. 变更检测与触发（D2）

- **事件源 = 编辑器「发布」动作**（不是保存——草稿随便改不触发）。控制台③手动送翻 = 备用通道，走同一条流水线。
- **检测**（零 diff 对齐）：源树切句 → 逐句查 TM：
  - 命中 approved → 复用译文（零成本）
  - 未命中（新句 / 源句改了一个字 → 指纹变 → 视同新句）→ 进送翻队列
- **结构同步**（同事件，纯代码零 AI）：源加段 → 镜像补壳（句全标未译）；源删段 → 镜像删；源重排 → 镜像跟随。镜像骨架恒 ≡ 源树。
- **连续发布**：草稿永远跟最新源，旧未审草稿作废。
- **控制台①开关 = 关**时：只检测 + 亮灯，攒待办，不调用引擎。

## 5. 翻译执行（D4 + 质量纪律）

- **引擎接口**：`translateSegments(segments[{id, text, contextBefore, contextAfter}], terms, style) → [{id, translation}]`。DeepSeek 实现；callAI 依赖注入可 mock（烧制台同款）。
- **上下文**：每句带前后各一句，仅供引擎参考连贯性，**回写只写目标句**。
- **提示词**：注入本页命中术语（lock/map）+ B2B 工业营销风格指令。
- **机器验收**（译文硬校验，不合格不落盘）：
  ① lock 词在译文中逐字出现（词边界匹配）
  ② map：源句含中文键 → 译文含固定英文、无该中文残留
  ③ 数字集合比对：源句数字 ⊆ 译文数字
  ④ URL/邮箱/链接原样保留
  ⑤ 覆盖率：送翻句 100% 有译文
- **失败纪律**（烧制台平移）：带拒收原因重翻 ≤ 2 次 → 仍败则该句标红进待审清单（人工介入），**不静默、不落烂译文、不拖垮同页其他句**；4xx/截断快败不重试。
- **幂等**：同一发布事件重复触发（连点/重试）不产生双草稿——TM 同指纹写覆盖。

## 6. 句状态机与发布门禁（D2 缺段照发的句级实现）

```
未译（TM 无记录） → 草稿（AI 已翻未审） → 已审（人审通过）
```

生产 build（dist）渲染规则：

| 句状态 | 生产渲染 |
|---|---|
| 已审 | 出译文 |
| 草稿 / 未译 | **该句不出**；整段无一句可出 → 该段不出（= 缺段照发） |

- **改过的源句 = 新句 = 缺席待审**（行为变更，明示取代旧 U-3"过期照显旧译"：句级粒度下源句一变指纹即变，旧译句已从源树消失，投影无处安放——故改为缺席。代价：该句暂时从英文页消失，审完回来；页面与其余句不受影响）。
- **页面永不下线**：只要有已审内容就发。门禁从"整页暂扣"（旧 neverTranslated）改为句级投影，页面级不再有"翻译不全 → 404"。
- **预览 build（dist-edit）**：全出——未译句出中文占位、草稿句出草稿译文，供审稿人看全貌。
- **SEO 联动**：语言版本有已审内容 → 自动进 sitemap / hreflang / 语言切换器（build 自动倒影，F4 接入）。

## 7. 控制台（`/__i18n`，挂 8092，与烧制台同级）

| 件 | 行为 |
|---|---|
| ① 自动翻译开关 | 全局配置项；关 = §4 只检测+亮灯 |
| ② 待审亮灯 | "N 页 / M 句待审"，逐页进入审阅 |
| ③ 手动送翻 | 批量处理全部待办（含存量补翻 D6） |
| ④ 术语表管理 | lock / map 两张表增删改 → 写 terms JSON，schema 校验（空值/重复拒收） |

- **审阅形态**：先纯文本句级中英对照清单（原句 / 草稿译文 / 原地改 / 过），fancy 分栏对照界面后补。
- 控制台数据全部从 TM + 源树现算，无独立状态库。

## 8. 术语表（D7/D8）

- 存储：`site/src/i18n/terms.<src>.<tgt>.json`，结构 `{ lock: [...], map: {...} }`。
- 读写收口：`loadTerms / saveTerms` 单点（R13 纪律：换库 = 改这一个文件 + 一次性导入脚本）。
- lock：词边界匹配，原样保留（型号/品牌/标准代号）；map：源含中文键 → 译文固定英文。
- 沿用现有词库内容（terms.zh-CN.en.yaml → JSON 一次性迁移）。

## 9. 旧 F3 零件去留

**砸**：`i18n_rev`/`translated_rev`/`i18n_fp` 三件套 · `i18n-touch.mjs`（手动兜底） · `i18n-apply.mjs` emit/from CLI（机制被流水线吸收） · 整页暂扣门禁（`neverTranslated`/`isPublishable` 的翻译部分） · terms YAML。

**留**：镜像 JSON + pageId 配对 · 族谱现算派生（registry） · 骨架 ≡ 源铁律 · run 抽取思想（升级为句级） · 发布门禁哲学（从页级降到句级） · 语言切换器 · 事件日志 `.i18n-events.jsonl`（动作类型扩展：source-publish / auto-translate / review / term-edit） · edit-server 保存链挂点（stampAfterSave 由「发布」事件取代）。
